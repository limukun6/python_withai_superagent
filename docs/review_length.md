# 审阅长度处理与证据范围

v0.35 中两个结构完整的 keep 回复分别写了 537、626 字符，超过旧的 500 字符限制。原实现保留有效 Planner 提案，并把后续决策交给已标记的恢复策略。因此模型仍可完成训练，但两个运行均不算完整 self_review / reviewer 对照。失败记录、费用和成绩不变。

v0.36 把 500 字符作为推荐长度，1200 字符作为硬上限。超过推荐长度的有效回复记入 `review_reason_length` 和 `review_reason_length_advisories`，不截断、重写或增加请求。原始 API 响应始终留在事件日志；结构化 reason 沿用去除首尾空白的规范化。超过硬上限、空值、非字符串、虚构事实引用和不合法替换仍失败。

模型输出上限仍为 2048 token，字符上限不等于 token 上限。课程费率、请求次数、单轮额度、持久任务累计额度和无自动重试规则保持。修改不保证今后所有回复都合法，也不证明自由文本解释正确。

验证包含两条真实失败回复的离线重放，500/501/1200/1201 字符边界、保留原提案及禁止额外调用。离线重放证明新解析规则能处理这些历史回复，不代表模型收到新提示后一定给出相同答案，不代表重跑后的实验成绩。下一次真实架构对照必须使用共同冻结的新版本，并重新记录完整运行状态。
