# 剩余九天：两条实验主线与七天研发计划

2026-11-20，根据“剩余九天、留两天准备演讲、两人都承担实验”的要求制定。本计划替代旧十天计划的后续排期；旧实验与协议继续保留。D1 为开始执行本计划的当天，不推算未确认的班级截止日期。

**范围修订：两位成员均使用 Codex 辅助开发。本计划以完整 SuperAgent 的任务覆盖、自主运行、效果与交付为目标；瓶颈实验是解释架构选择的组成部分。增加真实图像与强方法实验，并减少整合矩阵的重复划分来控制工期。** 开发助手是 Codex，运行时用于实验规划的模型仍是既定 DeepSeek-V4.1-Flash，两者不要混淆。

## 1. 目标、工时与分工

**D1–D7 完成研究、正式实验、报告主要内容与提交包；D8–D9 专门准备演讲和演示。** 第七天之后不再开新实验或加入新架构。每天按每人约 4 小时有效研发安排，七天共 56 人时；若每天只有 3 小时，采用第 11 节缩减方案。

| 人员 | 独立研究问题 | 自己负责的实现、实验和结论 |
|---|---|---|
| A：你与自己的 Codex | 陌生任务如何进入系统，如何理解目标并自主改进，最后交付可用模型？ | 任务接入、schema/数据检查、证据闭环、统一 CLI、预测导出；A1/A2、图像完整流程验证及部分 Q/C1/H；产出任务覆盖、纠错和自主完成结论 |
| B：队友与自己的 Codex | 系统有哪些足够强的解法，怎样在预算内发现并选稳好模型？ | 预处理/表征/分类器能力目录、队友方法模块接入、强基线、探索/复核调度；Q/B1、条件 B2 及部分 C1/H；产出效果、搜索与资源结论 |

每人都写模块、跑对照、分析正负结果、准备自己的两张核心图。每次合并做短时间相互复核，但不把任何一人固定成审查者。分工按研究模块，不按“一个人跑所有实验、另一个人整理报告”。

资源按已知一台 RTX 5070 8 GB 电脑安排，不假设还有第二台训练机。两人可同时编码和分析；重训练用一条队列轮流占用，共享 GPU 同时只跑一个作业。主要因果实验使用 CPU 可完成的候选和既定 Flash API，不引入本地大模型训练。

## 1A. 完整流程与最终系统验收

流程目标为：任务包/目标 → 数据与任务解析 → 训练内划分 → 方法与资源计划 → 建立可靠基线 → 执行实验 → 分析观测/更新记忆 → 调整方法或预算 → 复核选模 → 完整重训 → 模型与预测导出。所有性能实验都要通过同一个正式入口触发这条链，不能只有研究脚本能用新机制。

| 环节 | 当前基础与需完成的工作 | 验收 |
|---|---|---|
| 接入任务 | 已有 manifest、常见 CSV/数组、图像目录适配；补充声明与推断冲突检查 | 在受支持 schema 内换任务仍能加载；含糊标签语义有明确状态；无数据集名称路由 |
| 理解目标 | 任务类型、标签、主指标、文本对交换含义 | 声明指标贯彻提案、排序、复核与最终报告；二分类/多分类类别映射一致 |
| 数据处理 | 缺失处理、类别编码、数值尺度、文本特征、图像大小/通道 | 预处理仅在对应训练分区拟合，保存在最终 pipeline；无验证/测试泄漏 |
| 形成方案 | 依据类型、样本量、维度、类分布、资源筛选能力目录 | 至少包含快速基线与具有不同归纳偏好的强候选；真实配置与能力描述一致 |
| 建立基线 | 通用本地策略、快速可运行分类器 | 在早期形成可保留的有效模型；同时评价简单基线与强基线 |
| 训练与诊断 | worker 隔离、错误切片、配对预测与费用日志 | 每个动作有真实观测或明确失败；执行器错误与算法效果差分开 |
| 自主改进 | 证据更新、参数/表征/算法变化、预算选择 | 有运行中根据前次结果改变后续动作的可追踪证据；不手选下一个模型 |
| 选型与停止 | 配对复核、incumbent、成本与时限 | 按主指标自主选型；有资源预留和停止理由；保留有效部分结果 |
| 最终交付 | refit、序列化预处理与分类器、预测文件、执行记录 | 新进程可加载、预测行序和类别正确；概率列顺序正确；冻结模型后再评估 |
| 未见任务执行 | 同一代码、控制器、方法目录、依赖与规则 | 仅输入新任务包与预算即可自主执行；不临时加针对该任务的代码或人工选模型 |

目前 CLI 的标准 planner/allocator 与自定义 CheckedHistoryPolicy 实验入口并非全部打通。D2 前必须将计划里的 E/S 开关接到正式 CLI 与累计费用账本，最终不能要求学生在研究脚本里手工构造决策器。

## 1B. 通用性与较好效果分别设目标

**通用性覆盖。** 课程范围是分类，包括表格、文本和图像。开发集增至五个真实任务：现有类别表格、数值表格、单文本、偏好文本对，加一个真实图像分类任务。混合表格、文本+表格、缺失值、新类别、无外部验证集等用接口/完整流程测试补充；没有真实性能证据的类型标为工程支持，不能统称已验证性能。至少覆盖二分类、多分类、accuracy 和 macro-F1。

**算法能力覆盖。** 决策结构不能弥补空弱的候选空间。B 在 D1–D2 盘点并接入最小方法集合，优先用已经存在的模块：

| 类型 | 快速可用路线 | 较强/互补路线及约束 |
|---|---|---|
| 类别/混合表格 | 合法编码 + 线性模型 | 树集成/提升树，缺失与类别处理；按兼容 schema 适用，不按任务名称触发 |
| 数值表格 | 插补/标准化 + 线性模型 | 树集成、适合规模的核模型；按资源筛选，避免盲目跑大核矩阵 |
| 单文本 | 词/字符 TF-IDF + 线性分类器 | 词字符组合、另一合法分类器；课程允许且依赖已冻结时接入语义特征路线 |
| 文本对 | 按 preference/relation/symmetric 分别定义表征 | 词字符与语义特征；对称任务提供真正对称的绝对差/乘积特征，不翻转标签 |
| 图像 | 固定尺寸/通道处理 + 简单像素基线 | 通用纹理/梯度特征 + 分类器；如已有可用且课程允许的冻结视觉编码器，再加特征提取路线。8 GB 不承担从零训练大型视觉网络 |

目前 general_models 的 image 路线是展开像素后接 logistic、ExtraTrees 或 SVC，属于可运行基础，尚不能视为强视觉能力。图像方法接入与真实任务验证是主线必做；昂贵的视觉预训练升级可按工期取舍，未验证时明确限制自然图像效果。

队友远端的 method_choice/minilm 等模块已有候选与实验，先审计依赖、课程模型适用范围、数据隔离、成本，再按能力接口接入可复用部分。预训练资源资格未确认、权重未冻结或模型依赖不可复现时，不作为最终依赖。已有强候选不应因为本研究分支还没合并而被忽略，也不应整体合并大量实验代码造成控制器分叉。

**较好效果的评价。** 同一划分与资源上限下同时比较多数类/简单基线、可执行强本地搜索基线、最终 Agent。主指标逐任务报告，另列完成率、最坏退化、运行时间。至少先证明系统有能力调用强方法，再评价 LLM/反馈是否增加价值。若最终 Agent 与强基线相当但更贵，默认保留强本地选择；结构贡献如实报告为可靠性或覆盖改善。

这些是验收目标，不保证所有未知任务均达到高分。通用性、效果和自主性分别需要实测；一台机器与七天工期无法证明对任意数据分布都有效。

### Q：算法能力与效果覆盖实验（主线新增）

五个真实开发任务 × 原有方法目录/补齐后的方法目录 × 一个固定开发划分，共 10 条完整自主路径。两组使用同一按合法方法路线覆盖的本地控制器、相同预算和选择协议；变更仅为方法目录与相应合法预处理能力。最多 110 次拟合、0 LLM 请求。该实验衡量可执行方法能力的贡献，不能归因于 LLM 推理。C1 的六组再共享补齐后的同一目录。

A 负责图像任务的端到端 Q 路径与输入/输出验收；B 负责方法实现及其余任务 Q 路径。B1 的原目录/源码若不等于 Q 冻结版本，不直接拼表。Q 必须在最终代码版本复跑或按一致版本执行，开发小试结果只作为开发依据。预计机器 1–3 小时，开发/分析约 6 人时；通过减少 C1 重复划分和取消 D4 可选新功能腾出时间。

## 3. 共同协议：先确定接口，避免两条线互相等待

D1 用 45 分钟冻结以下最小接口。A 与 B 分别实现，D2 只检查接口连通，不等待对方完成全部研究。

```text
TaskContract:
    input_kind, label_domain, primary_metric, maximize,
    pair_semantics, split/group rules

CandidateCapability:
    candidate_id, input/label support,
    swap_label_rule = flips | preserves | unsupported | unknown,
    representation, estimator_spec, expected_classifier_fits,
    origin = static | recipe | registered

EvidenceRecord:
    evidence_id, trial_id, candidate_id, split_id, metric, value,
    source = task | declared_config | fitted_artifact | measurement,
    status = observed | contradicted | unverified,
    scope, supersedes/contradicts

Observation:
    primary_score, aligned_predictions, actual_estimator,
    actual_fit_count, elapsed_seconds, execution_status, evidence_records

Scheduler:
    next_action(history, budget) -> explore | confirm | finalize
```

执行器产生可核验事实，LLM 产生下一步提案和待检验解释。任何 `confirmed` 都必须能回到具体事实对象。真实时间保留在资源账本；LLM 决策输入不使用无关路径、日志时间戳、机器噪声的小数位。若调度需要耗时，只提供冻结的成本档位或同任务已观察成本，并在两组一致使用。

文件归属建议：A 主改 data/schema/CLI/predict 的流程接入，以及 task_semantics、estimator_facts、contracts 的证据部分、checked_history_policy、hypothesis_memory、explanation_audit/prose_claims；B 主改 general_models、方法模块、evidence_schedule、resource_allocation、候选注册适配、MetricSpec 相关调度和实验 runner。benchmark 的共用挂接由 A 维护，B 通过 Scheduler 接口接入，不同时改同一控制循环。

两人从同一基线创建 `codex/evidence-loop` 与 `codex/budget-search` 分支。D1 先将现有未提交改动整理成共同基线；每晚交换提交，不在对方工作区覆盖文件。分支名称是执行约定，本计划没有创建分支或启动实验。

两个 Codex 会话各自读取本计划、自己的模块范围与共同接口。交接记录固定为：基线 commit、实现开关、运行命令、数据/源码指纹、已完成实验、结果文件、下一步和阻塞。两个开发助手不会自动共享对话或进度；以 Git 提交和运行产物为共同事实。不得同时在同一个可变工作区跑源码敏感实验，两条实验线从明确提交的独立 checkout 执行，统一训练队列不变。

## 4. A 线：任务理解与证据驱动纠错

### A1：检查器是否真的可靠

**假设**：绑定任务、实际配置与具体测量的检查器，能减少错误事实被采纳，且不会靠拒绝所有提案获得好看结果。

先修复复核报告中的问题：recipe 隐藏翻转增强、0.5 交换歧义、Ridge/SVC 错误映射、未完成试验被确认、跨试验/跨指标数字匹配、否定语义、检查结果丢失、无 assessment 时不触发审计。

实验设计：96 个离线案例，8 类各 12 个：任务语义、实际配置、试验身份、指标/划分身份、否定/未来语态、整体与切片冲突、记忆失效、失败状态。每类包含合法、错误和信息不足情况。48 个用于开发，48 个封存；封存例用不同模板与取值，不简单复制开发句式。两人各提供一半初始案例；A 不为封存例逐句加规则，B 仍继续自己的 B1。

对照：旧规则、修复后规则。主要指标为错误确认数/错误例数、合法误拒数/合法例数、未知被误当事实数/未知例数、可核验覆盖率；每类分别给原始计数。人工标签不能来自同一个被测检查器。自由文本不可靠时允许 unverified，但覆盖率必须同时报告。

另做 8 个小型训练探针：合成 preference/symmetric 两种语义 × 两种执行路径 × 两个固定划分。检查实际传入训练器的特征与标签，而不只看元数据。它们只证明工程性质，不证明真实任务性能。非法语义路径作为受控反例，不能参与正式任务选模。

预算：96 案例 × 2 个检查版本；最多 8 次分类器拟合、0 API。机器约 5–15 分钟，准备/实现/分析约 6 人时。交付 `A1_cases.json`、预期标签、按类混淆表、两条训练输入轨迹。

### A2：收到正确反馈后，下一步是否更好

**假设**：在同一真实历史上，显式核对与记忆能减少错误事实延续，并改善下一动作的实测效果。

四个开发任务各用本地统一策略执行前三个实验，冻结前缀长度 1、2、3 的状态，共 12 个真实状态。状态按固定位置取，不为了出现“成功纠错”而挑选；自然轨迹若没有某类错误就报告缺少该类样本。人工故障注入留在 A1，不混成自然发生率。

每个状态比较两组：R 读取原始事实与历史；E 读取相同原始事实，额外获得证据检查和带状态的记忆。模型、输出 schema、温度、合法动作菜单相同。每组只一次 Flash 请求，配对执行顺序轮换，共 24 次请求。答案先封存，再测动作，不能挑选更顺眼的回答。

衡量两层：

1. 决策行为：错误陈述是否延续、是否准确引用失败、是否提出可执行动作。重复同族本身不计错，撤回错误声明与真正修复目标组分别计数。
2. 动作质量：每个不同动作在两份共同训练内部划分上拟合；决策未看到这两份评分。报告 E−R 的主指标差值、胜平负、切片收益与整体代价。相同动作只拟合一次并标明复用。外层留出不用于选择下一动作。

上限：准备状态 4×3=12 次拟合；12 状态×2 动作×2 划分=48 次拟合；合计 60 拟合、24 请求。机器约 30–90 分钟，人力约 4 小时。固定状态实验是机制诊断，不作为完整 Agent 的最终任务成绩。

可选 A3：若存在少数状态主导结果，对同一 12 状态做一次预声明的无关表述扰动，两组共再 24 请求、最多 48 拟合。衡量提示稳健性，不声称这些变体是独立模型抽样。重复 response_id 单独分组；不反复加 nonce 追求想要的结果。

## 5. B 线：有限预算内探索与可靠选模

### B1：让预算跟随证据，而不是固定轮数

**假设**：对明显落后的候选减少重复确认，把预算留给新路线；对接近或排名不稳的候选增加配对复核，可以改善最终质量或减少浪费。

已有 interleaved_routes 已实现探索/利用交替，不能重新包装成新贡献；已有 evidence_schedule 是 accuracy-only 原型。本轮研究点是把调度建立在统一主指标与可追溯的配对观测上，接入自主运行入口，并跨任务检验。

两组共同使用修复后的合法候选库、相同 anchor、训练器、数据划分和最终 refit。

| 组 | 调度 | 分类器拟合上限 |
|---|---|---:|
| F 固定 | 4 次搜索，前三名各追加 2 次确认，最后 refit | 11 |
| S 证据调度 | 搜索与确认共最多 10 次，根据已观察结果切换，预留最终 refit | 11 |

S 最小实现：先完成 3 个不同候选的探索；对 challenger 与 incumbent 使用同划分的主指标差值，必要时追加共同划分；只有达到预登记晋级规则才替换 incumbent；证据冲突则保留旧模型并记录未决。剩余预算不够公平比较时不强行宣布赢家。新候选仍由已有通用路线策略提出，避免同时更换所有部件。

规则在 D2 小试后一次冻结：归一到 [0,1] 的主指标最小实际差值暂用 0.002；追加复核后至少两份共同划分方向支持且平均差值达阈值才晋级。这个阈值是工程规则，不是显著性检验。对没有共同可比分数的候选不混算均值。若超时则记失败和实际成本，不能视为零耗时。

accuracy 使用配对预测差值，macro-F1 使用相同重采样索引重算两模型分差；不能套用单模型 accuracy 的二项标准误。改好 headroom 脚本，先用已有产物重算 SMS 主指标，再选择是否值得扩候选。

开发矩阵：4 个任务 × 2 个预登记开发划分 × 2 组=16 条自主路径，最多 176 拟合、0 API。报告最终外层主指标、候选覆盖、第一名被推翻次数、每次有效晋级的花费、完成率、真实拟合数和墙钟时间。固定预算上限相同不代表实际消耗相同，分别展示。

耗时：机器约 1–3 小时，工程/分析约 8 人时。若要分离“规则自适应”与“多探索”的贡献，可条件追加固定 6/2 组，8 条路径、最多 88 拟合。只在 S 的结果与 F 有区别时做，旧 4/3 对 6/2 结果继续作为背景，不再原样重复。

### B2：诊断出来的问题，是否有对应动作可做（条件实验）

只有 B1 显示现有动作空间缺少有效替代、且 D4 前有余量才启动。优先复用现有白名单 recipe 和队友已验证的候选，不在七天内实现任意 Python 生成或新的神经网络训练。

选择两种已支持组合的开发任务，每任务一个固定划分，比较三组：原目录 + 原搜索器；预先列全合法组合的扩展目录 + 同一搜索器；同一完整组合空间 + 按观测提出候选。每组仍最多 11 拟合，新增动作必须占搜索名额。前两组测“可选动作变多”，后两组测“提出/选择动作的方式”，不能把扩库收益全部归给 Agent 推理。

最多 6 条路径、66 拟合、0 额外 API。机器约 30–120 分钟，人力最多 4 小时。若当前只有文本 recipe，结论限定于文本组合；它不是四模态通用生成能力。若没有更好的候选，记录动作空间上限，不继续无限调参数。

已有四任务均属于开发集：优惠券、标题偏好、Dry Bean、SMS；Q/C1 新增的图像开发任务同样属于开发集。它们看过成绩后不能重新命名为 unseen。

机器约 1–3 小时，新数据准备/分析共约 4–6 人时。若单任务过大，D1 按资源与数据规模预先确定子集及抽样规则；不按模型成绩挑子集。

### Released：正式结果与可执行模型

## 9. 冻结、晋级与停止条件

1. **正确性门槛先于性能。** 没有实际训练输入核验、存在已知错误确认、检查结果未到下一轮时，不启动大规模付费矩阵。A1 封存集存在错误确认就报告并修复，不能只删失败例。修复后的旧封存集成为回归集，不能继续称未见测试。
2. **按开发证据选 F*。** 先要求无已知数据泄漏/非法训练，所有预登记任务均可自主完成。相对 L0，各任务平均主指标退化不超过 0.5 个百分点，且至少两个任务平均提高 0.2 个百分点；或者各任务退化不超过 0.2 个百分点且总中位耗时降低至少 20%。这些是工程选择门槛，不是统计显著性证明。
3. 过线多组时按五任务等权平均差值、最坏任务退化、实际 API 数、机器时间依次选，排序 D4 前写入协议。任何单分区退化超过 2 个百分点列为风险案例，不默默平均掉。没有组过线则默认 L0，证据核验保留为不会改变合法动作的诊断功能。不能为证明创新而强行用更差的策略。
4. **冻结后的 H 不再用于晋级。** 即使 H 上退步也保留并解释；它测的是冻结选择规则的外部表现。严重执行故障可以修复，但如实撤销其未见性能证据身份。
5. **没有增量就停对应方向。** B1 所有有效配对同选且同预测，B2 无可执行新动作，或 A2 只改措辞不改错误/质量，都要明确写成边界，不继续碰运气加 seed。没有独立采样保证时不靠重复同请求取多数。
6. **D4 功能截止，D7 研究截止。** D5 之后若修改实质代码，标记新版本并重跑受影响正式组；来不及就减少正式结论范围，不能把不同版本拼成公平对照。

## 10. 两条研究线怎样得出可讲的实验结论

每条结论使用同一模板：

> 瓶颈：Agent 在什么具体情况下会出错？
> 结构：我们在哪个决策点加入了什么信息或规则？
> 实验：比较哪些组、控制什么、覆盖哪些任务与划分？
> 结果：主指标/错误数改变多少，耗时、fit、API 与失败多少？
> 边界：可以支持什么，尚不能证明什么？

A 的核心图：按错误类型的错误确认/合法误拒对照；真实轨迹的“声明→测量→核对→下一动作”及动作实测分差。B 的核心图：固定/自适应预算去向与 incumbent 演变；同预算最终成绩与时间。共同图：六组消融及两个冻结迁移任务的逐任务结果。

若 A1 可靠性改善而 A2/C1 分数无稳定增益，结论是“减少了可检查事实错误，尚未证明准确率收益”。若 B1 只省时间，结论是效率；若 expanded 菜单改善而 online 选择不改善，结论是动作空间贡献。若仅某类任务有效，要讲清适用范围。负面结果同样回答架构选择问题。

每条完整路径保存：源码/配置/依赖指纹、任务与实际行 ID、候选全集及能力描述、每步决策输入输出、证据与预算记录、预测、最终模型、失败状态、token 和课程折算费用。汇总分开统计 planned/completed/failed、attempted/completed fits 与实际请求数。旧日志复用必须满足源码、数据划分、候选和执行路径身份一致；否则只作为历史开发证据。

## 11. 工期不足时怎样缩减

优先取消 D4 的所有可选扩展；其次将 B1 开发从两划分减为一划分（省 88 拟合）。C1 已减为五任务一个划分，不再假装有重复划分证据。再不足时保留 L0、R0、E0、E1 四组（省 110 拟合、15 请求），明确无法单独识别完整交互作用；不要取消图像与强方法验证。H 保留两种真实任务，必要时各一划分（省 66 拟合、12 请求）。

这样保留“模块有效性→整合消融→新任务迁移”的证据链，而不是保住很多同任务重复试验却取消通用性。保留两天演讲不变。若每天只有 3 小时，从 D1 就采用缩减版，不等 D7 才发现来不及。
