# 小样本任务的候选资格回归

在五折实验运行期间单独登记。新策略直接沿用了旧策略的分组函数。旧策略会要求旧提名区本身包含两个类别。新试用策略实际只使用试用、提名与确认三个区，旧提名区已经与其他组一同重新划分。本实验检查是否有满足三个实际角色要求、却被旧条件提前转交通用调度的任务。

用 45、90、180 个匿名独立文本组，正类比例 5%、10%、20%，每个组合在固定随机数种子 241124 下随机放置正类 200 次。正类数四舍五入且至少为 2，核对比例只用于工程覆盖。根据已登记的两次哈希和截断规则独立重建实际三个角色。每个角色至少四个组且两个标签齐全，作为预期资格。若确认旧代码存在额外拒绝，只修复该资格条件。比较前后 1,800 份配置，确保全部改动只覆盖真正满足三角色资格的情况，五份课程开发包行号完全相同。

再用一个确实触发差异的匿名 ZIP 从统一 CLI 跑到首个拟合边界，分别记录修复前后的实际路由。此栏是工程资格和任务可达性，不推断真实任务性能。新增分类器拟合、模型 API 均为零。
