队友的指定验证纪录是 **1,549 / 2,030（76.31%）**，对应提交 `534d599`。B 线在独立分支上增加了可选的表格模型、较长训练预算下的探索，以及一次融合前复核。九次匿名任务运行显示，扩展后合计多答对 3 道，收益仍会随划分改变。本批保留队友的指定验证纪录。[队友交付记录](../../research/task1_context_agent_01/completion.json) · [本批结果及源指纹](../../research/task1_feedback_extension_1127/results.json)

## 相同预算的三折对照

从课程 train 中另取 6,493 行，按整行特征分组得到新的五折，依次评估三个外层留出折。每次交给 Agent 的只有匿名训练包和无标签预测包。各路都允许最多 32 次拟合，时间上限 1,800 秒。程序先完成全部九次选模、重训、独立进程预测，随后一次打开三个留出的答案。不同折会复用部分训练样本。

| 对照 | 1,299 行 | 1,301 行 | 1,294 行 | 合计准确率 |
| --- | ---: | ---: | ---: | ---: |
| 队友目录和调度，显式放宽次数 | 981 | 984 | 993 | 2,958 / 3,894（75.96%） |
| 增加两类模型，保留原赢家并尝试不同路线 | 989 | 984 | 988 | 2,961 / 3,894（76.04%） |
| 在上一路线基础上，单留一批训练数据复核融合 | 992 | 984 | 985 | 2,961 / 3,894（76.04%） |
| 用上面常规扩展版已训练的折模型贡献四分之一的概率，仅作推理对照 | 991 | 989 | 984 | 2,964 / 3,894（76.12%） |

常规扩展版比队友的同预算入口改对 85 道、改错 82 道。增量为 **+0.08 个百分点**，按整行特征组做配对重采样，95% 区间为 **−0.59 至 +0.74 个百分点**。预定晋级条件包括至少两折上升、单折回落不超过 0.30 点、总体提升至少 0.30 点。本次保持课程指定验证标签封存，正式测试和 H2 也保持封存。[晋级规则](../../research/task1_feedback_extension_1127/three_fold_anchor.json)

两次常规冷启动选择了“条件属性树与 TabICLv2 各半”，另一次只选择队友的情境树。独立复核在其中两个划分交付了单棵条件属性树。供给候选和权重文件是运行环境的一部分，参赛方法、何时停止和最终成员均由程序根据训练侧结果决定。三折展示的是同一任务上的决策变化，跨任务性能还需另外验证。

## 哪些尝试有证据

- 第一组独立外层对照有 1,624 行。旧版 10 次、旧目录 32 次、扩展目录 32 次、再开放额外探索，实际各用 10、18、21、23 次，均答对 1,230 道。早期筛选时有一对新模型在两批确认中净增 13 道，另行用所有 6,493 行拟合后，在外层比单独的队友情境树少 3 道。
- 表格预训练模型使用发布者的 `TabICLv2`，通过已校验的离线权重在本机 GPU 推理。附加画像与情境的表示，以及按训练反馈自动选列并训练五个局部上下文的表示，均已真实运行。程序提名的前一种组合在两个后续面板合计少答对 9 道。[TabICL 模型卡](https://huggingface.co/jingang/TabICL)
- 从随机权重训练了两版八头 TabM。入选组合在后续面板净少 5 道。另完成两版 XGBoost 和一版 Explainable Boosting Machine。入选的 XGBoost 组合一批少 4 道，一批多 4 道，合计持平。[TabM 作者实现](https://github.com/yandex-research/tabm) · [XGBoost 类别数据说明](https://xgboost.readthedocs.io/en/stable/tutorials/categorical.html) · [InterpretML 模型说明](https://interpret.ml/docs/python/api/ExplainableBoostingClassifier.html)
- 两批训练面板里，原组合错了 400 道，已有模型中至少一个能答对其中 210 道。实际需要在答题前识别该听谁。用样本属性、置信度与模型分歧来学习何时改判，四折预测反而净少 7 道，程序退回原方案。单学概率修正则在两批后续面板均无净变化。
- 九次普通入口、第一组四次入口、默认兼容性重跑与开发实验合计 **281 次已完成的任务模型或决策器拟合**。一次真实 TabICL 调用在输入类型校验时失败，另行留档。两次小型模型环境检查单列。TabICL 每次调用使用四个预处理视图，TabM 每个网络共享八个输出头，EBM 内含四袋。新增校园模型请求和输入、输出 token 均为 0，本批模型 API 费用为 **¥0**。

## 接入与交付

队友原提交与本分支默认 10 次训练入口，用完全相同的课程原包和特征在本机各跑了一次，各自重新启动预测进程，产生了字节一致的 2,030 行预测。该本机文件与队友已经评分的原交付文件指纹不同，因此 76.31% 只引用队友的历史成绩。

显式请求超过 16 次训练时，普通入口会根据数据和任务限制开放额外候选。使用 `--fit-limit 32` 启用较长的本地探索。加 `--feedback-reflection fusion-holdout` 可以复现实验中的单独留出复核。原训练机会内的默认候选目录保留。通用运行示例如下。

```sh
python -m unified_agent solve TRAINING.zip --prediction-input FEATURES.zip --fit-limit 32 --run-dir RUN --output predictions.csv
python -m unified_agent predict FEATURES.zip --run-dir RUN --output replay.csv
```

可选模型依赖在 `requirements-ab-table-tested.txt`。权重使用 `jingang/TabICL` 的 `tabicl-classifier-v2-20260212.ckpt`，修订号 `4dcd344ece2c00be9e831fdd35bed57b5ad83e19`。提供标准 Hugging Face 本机缓存，或设置 `SUPERAGENT_TABICL_V2_WEIGHTS` 指向该权重。入口验文件长度和 SHA-256。任务禁止预训练时会排除该方法。

一个真实的双模型交付从 **1,068,778,653 字节减至 9,827,645 字节**。程序在新进程第一次预测时重新计算注意力缓存。1,299 行的类别和每个类别的概率全部一致，首次耗时从 3.92 秒变为 11.67 秒。可复用的 110,368,038 字节公共权重另计，两版均需相同的权重。课程数据、训练权重和逐行预测保存在本机。[权重与校验值](https://huggingface.co/jingang/TabICL/blob/4dcd344ece2c00be9e831fdd35bed57b5ad83e19/tabicl-classifier-v2-20260212.ckpt)
