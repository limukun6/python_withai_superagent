# DeepSeek 更新复核与下一步优先级

2026-11-20。复核本机 `runs/integration` 未提交改动，并 fetch 了 GitHub。远端队友分支 `superagent-v2.0（hjl）` 更新到 `d750c7b`；本机研究分支仍在 `39c0522`，本次看到的新增结构尚未提交。两者的实验口径不同，不能合并成绩表直接比较。

结论：任务语义、训练对象核验、解释审计和外部任务扩展值得保留，但需要先修复检查器自身的正确性与接入闭环。暂不以本轮检查器输出证明“Agent 已能可靠纠错”，也不因一次决策重放就停止反馈研究。

## 已有进展与证据边界

| 瓶颈 | 新结构/实验 | 已能支持什么 |
|---|---|---|
| 两列文本可能被误当成偏好任务 | 任务语义契约、候选过滤、交换探针 | 已有检查入口；下面的反例表明过滤与探针仍有漏洞 |
| 候选名与真实分类器不一致 | worker 记录拟合对象，生成 configuration_fact_check | 能在运行记录中核对实际对象；结果尚未进入下一轮决策 |
| LLM 解释可能引用错误事实 | 分类器、试验号、百分数的规则审计 | 已有部分断言抽取；confirmed 目前不能解释为整条陈述正确 |
| 单次 LLM 选择可能不稳定 | 12 状态 × 2 上下文 × 2 重复，48 次请求 | 记录到响应复用迹象与动作变化；尚未测出检查对决策质量的稳定作用 |
| 仅有两类真实任务 | Dry Bean、SMS 两个外部开发任务 | 统一入口跑通，多分类 accuracy 与单文本 macro-F1 可运行；不是冻结后的迁移验证 |

复核运行了 74 项相关单元测试，全部通过。另用小反例检查边界，发现下述问题。没有启动新的付费调用或完整训练批次。复用日志确认重放批次为 48 次调用、课程折算 0.371774 元；两个新任务的已有全候选探测为 7 + 6 次拟合、19.8 + 21.8 秒。

## P1：对称任务仍会训练到错误标签

位置：`task_semantics.py:33,66`，`recipe_models.py:67,89`。

过滤器只读 `params.swap_augmentation`。`semantic` 的四个 recipe 候选没有该字段，因而被视为可保留；但 `RecipeTextModel.fit` 在 pair_text 上无条件做 `matrix=[X,-X]`、`labels=[y,1-y]`。

离线复现：声明 symmetric、选择 semantic，契约返回 accepted，剩余 4 个候选。拦截 LogisticRegression.fit，在分类器实际拟合前检查输入：4 条原始数据已变成 8 条，后四个标签等于 `1-y`。这不是“尚无足够强的对称候选”，而是被放行的候选依然有错误语义。

改法：给每条可执行候选提供统一能力描述（输入类型、标签域、交换标签规则、表征规则），由静态候选、recipe 与动态注册候选共同使用。字段缺失不能被当成“不翻转”。训练执行前再次验证解析后的候选。先关闭这条错误放行路径，再增加真正的对称表征，例如绝对差与逐元素积；有向关系任务单独表达方向。

验收：同时覆盖静态、recipe、动态候选；真实拦截训练输入，检查标签转换，而不只断言参数字段。使用合成数据验证交换性质，使用真实对称关系任务验证性能，两种证据分开报告。

## P1：核对结果没有形成决策闭环

位置：`benchmark.py:298,314`，`contracts.py:140`，`checked_history_policy.py:23,34`，`explanation_audit.py:34`。

1. worker 后的 configuration_fact_check 写入 history，但 DecisionState.build 的字段白名单没有它，也没有 observed estimator。build_memory 同样不记录这项核对。实测把 contradicted 注入历史，构建下一状态后，该字段在 history 与 memory 都消失。因此下一轮 LLM 看不到刚发现的工具事实错误。
2. benchmark 仅在 proposal 包含 assessment 时执行解释审计。CheckedHistoryPolicy 的输出契约不要求 assessment，已有 checked-loop 提案因此不能保证触发审计。
3. 审计字段不含 hypothesis；文档展示的旧错误 “A char n-gram SVM...” 正在 hypothesis 内。手工回放时抓到该错误，不等于线上运行入口已覆盖它。

改法：统一检查结果为有来源的 evidence records，提供 trial、candidate、事实类型、声明、观测、判定和适用范围。确定哪些检查属于两组共同事实、哪些属于消融变量，再显式投影到下一轮。对所有具备解释字段的提案做审计，不依赖另一套策略特有的 assessment。hypothesis 中的可核验配置事实应检查，未来性能预测仍保留为未验证假说。

验收：通过模拟决策客户端走完整的“提案→训练回报→核对→下一请求”路径，确认错误反馈确实送达，错误提案不会被写成已确认知识。初期不增加额外修复调用，使用下一次原定决策预算处理，避免破坏对照公平性。

## P1：解释检查会把错误陈述标成 confirmed

位置：`prose_claims.py:147–176`。当前有两个同名 check_prose 定义，前一个被覆盖，可顺带清理。

复现历史：trial 1 搜索 accuracy=60%、训练 accuracy=90%；trial 2 搜索 accuracy=70%、训练 accuracy=95%。

| 输入陈述 | 当前结果 | 问题 |
|---|---|---|
| Trial 1 search accuracy was 95%. | 试验引用和百分数都 confirmed | 95% 实际来自 trial 2 的训练分数 |
| Trial 3 achieved 95%. | 两项都 confirmed | trial 3 尚未完成，不能拥有历史实测成绩 |
| Trial 0 achieved 90%. | 两项都 confirmed | 不存在 trial 0 |
| The selected classifier is not logistic regression. | 分类器 confirmed | 抽取忽略了否定词；实际事实为 logistic |

根因：百分数只要与任意历史指标相等就确认；试验号只检查是否超过 len(history)+1；分类器只匹配词，没有绑定主体、否定与时间。

改法：先核验结构化引用 `(trial, split, metric, value)`，再生成可读文字。自由文本无法可靠绑定主体时记为 unverified 或 number_match_only。区分已完成事实、下一实验计划和未来假说；实际试验号使用集合检查。不要把低覆盖的关键词匹配包装成陈述正确性认证。

验收：独立构造真假陈述集，包含错试验、错指标、训练/验证串用、否定、未来语态和混合分类器指代；报告错误确认率、误报率与覆盖率。历史 43 条被程序判为 confirmed，本身不能证明“43 条全真、零误报”，需要独立人工标签。

## P2：交换探针存在不可辨认情形

位置：`task_semantics.py:110`，`benchmark.py:369`。

实测 `swap_behavior([0.5,0.5],[0.5,0.5])` 返回 flips，但这组预测同时满足对称与互补，两种误差均为 0。当前先判断互补，导致顺序决定类别。文档真实探针的互补误差约 0、对称误差 0.0724，也都在现有 0.10 阈值内，按此判定标准并不能唯一辨认。

改法：保留两个独立检查；两者同时通过时记为 ambiguous，报告预测离 0.5 的距离。未声明任务语义时，consistent_with_declaration 应为 null，而不是 True。行为探针只检验模型约束，不能推导任务真实含义；再好的探针也不能替代任务描述与标签语义。

## P2：真实对象核验仍含错误映射

位置：`estimator_facts.py:15,61`。

实测 RidgeClassifier 被报为 logistic；SVC(kernel='poly') 被报为 rbf_svm。这两者不是相同算法。新任务引入这些候选后会错误确认或错误否决配置声明。

改法：保留原始 module、class 与关键参数；区分 ridge、linear_svm、rbf_svm、poly_svm 等，或用统一 svm family 加 kernel 属性。集成模型显式记录组合及组件，不能伪装成一个分类器。未知事实允许 unknown，但不能猜一个最接近的已知名称。

## P2：重放与迁移实验的评价工具需要修正

### 重放

实跑文档中的当前 `replay_same_history.py --verify`：12/12 请求均报 history MISMATCH。原因是生产 decision_context 已删 training_seconds，验证脚本仍使用最新函数重建旧请求。历史上曾验证成功不必然是错，但现在的复现命令已经失效。

需要分离：历史原样重放（直接使用冻结请求及原有调用参数）、新版输入投影重放、两组同状态对照。保存源码版本、prompt schema 版本和完整请求哈希。当前 verifier 比的是解析后字典，不是 HTTP 请求字节，文档也应按实际比较范围措辞。失败时应在首个异常就结束整个批次；当前 raw 出错后还会进入 checked 循环再发请求。

日志确有 24 个非空 response_id 各出现两次，提示响应复用；不能仅凭 ID 与用量证明服务端缓存机制、后台模型版本恒定或实际重复扣费。same served_model 只能说明返回的别名相同。费用应继续标为课程折算，真实扣款待账单。

7/12 上下文分歧、3/12 跨时段分歧、3/4 微小扰动分歧来自不同且很小的样本，不能直接用分歧比例比较“收益与噪声”。动作变化不等于动作质量变化。原来的 +1.6579pp 是真实单次观测，应保留，但不能作为稳定结构收益；也不能改写成已证明是噪声导致。

### 外部任务

`probe_task_headroom.py:52` 始终用 search_accuracy；SMS 主指标却是 macro_f1。因此当前 SMS 的 best_score、排名和空间宽度不是项目主指标的结果。应从已有 worker 产物读 primary_metric/search_score 重算，不必重新拟合。

单个 accuracy 的二项标准误也不是同一批样本上两个候选分差的标准误。应使用逐行配对预测；accuracy 可报告配对差异，macro-F1 可使用配对 bootstrap。全候选最优值只作为开发集内参考上界，不作为无偏能力估计。

两个外部任务已经看过验证成绩，作为开发任务合理。正式迁移结论需另留规则冻结前未查看性能的真实任务；新划分种子不能代替新任务。

## 下一轮执行顺序与预算

| 阶段 | 工作与问题 | 预算/耗时估计 | 通过条件 |
|---|---|---|---|
| A | 修复语义过滤、核对接入、错误确认、对象映射与重放分层 | 工程约 3–5 小时；API 0 | 上述反例和完整决策链测试通过 |
| B | 用已有预测重算两项外部任务的主指标、配对差值；整理历史请求 | 约 30–60 分钟；API 0，新增拟合 0 | 指标一致，历史/新版请求分开可复核 |
| C | 4 个开发任务各取 3 个冻结历史状态，比较原始与核对反馈 | 12 状态 × 2 组 × 2 个预声明提示变体=48 次请求；估计 15–30 分钟 | 每状态两组配对，执行顺序平衡；不把变体或重复 response_id 当独立样本 |
| D | 对分歧动作训练，在训练内部的独立评估部分评价选择质量；再做完整循环 | 完整循环 4 任务 × 2 划分 × 3 策略 × 11 拟合=264 拟合；两组 LLM 各 3 决策，共 48 请求；约 1–3 小时 | 相同候选空间、预算、复核策略；逐任务报告成绩、失败率、耗时、fit/API 数 |
| E | 规则冻结后的新真实任务迁移 | 数据与运行预算另冻结，不提前看成绩 | 区分工程兼容性、任务内重复与真正跨任务迁移 |

C 的两个提示变体只用于稳健性审计，不宣称独立采样；重复响应单独分组。不要为“绕过缓存”无限追加请求。D 的分歧动作训练量另计，静态候选可复用同一冻结配置下的实测预测，不能混用不同划分或旧源码结果。耗时来自目前两类发布任务约 30 分钟/一轮及外部轻量任务几十秒的测量，属于估算；先用小批校准。

主要指标先看“是否减少错误事实被采纳、是否让下一动作更合适”，再看完整循环的最终性能。只有换了动作没有改善质量时，应报告机制影响而非性能提升。即使最终 accuracy 不提高，可靠拒绝错误语义、保留未知事实、正确报告局部失败仍是有独立证据的通用能力。
