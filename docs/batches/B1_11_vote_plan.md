# B1-11 · 三个候选的现成判断能否补对错例

B1-10 发现部分任务中多个候选会错在不同的行。本次用可在预测时实际执行的简易规则检验这种互补性。仅读 B1-07/08 四任务、两开发划分、固定调度的八条路径，每条都已有四个候选探索和前三名在两份划分上的复核。完整纳入 16 个复核区块。新增模型拟合、模型推理、外层评分与 API 均为零。

**先锁定人选。** 单独的准备进程只读每条路径第一次复核前的状态。四个已探索的候选按任务主分降序、名称升序取前三，第一名为基准。八组三人名单和首轮状态摘要全部写盘后，再启动独立评分进程。后续表现不参与成员、权重或平票规则的选择。

**规则固定。** 逐行使用三个成员各自当时在同一复核划分上留下的预测。只有另两名一致时才用它们的判断，其他情况沿用第一名。所有输入都用预测时可得到的信息，无需样本答案。比较该规则与首轮第一名的主分、获救和丢失的正确行，以及所有三成员可能补救的行数。短信按 macro-F1 配对重算，保留所有任务全部结果。

**检查观测复用。** 每份复核同时报告所有行，以及剔除首轮探索评估中已出现过的组后剩余的行。组的定义沿用原任务，标题共享同一标题的行在同组。两份复核也可能重叠，列出实际交集，不将四个区块视作四次独立任务。少于三个完整可比成员时报告缺测，不换成员或删区块。

每任务只有在两份开发划分的四个复核区块全都主分高于首轮第一名、平均至少高 0.2 个百分点时，才标成值得另做等预算部署验证。其余结果保留原样。原固定路径用 4 次探索、6 次复核和 1 次重训已占满 11 次；按三个成员全量重训需 13 次，后续若要部署须在原预算内重新分配。课程验证、正式测试、H1/H2 和当前部署策略均不参与。
