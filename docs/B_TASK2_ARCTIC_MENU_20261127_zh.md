# 给统一入口多一个 Arctic 编码器后，Agent 怎样选

在原有资源目录旁新增 Snowflake Arctic Embed S 的公开权重，固定发布版本和文件指纹。Agent 会识别发布者声明的池化配置，开发者可以用同一接口提供其他兼容的句子编码器。运行时由 Agent 决定是否训练、采用或融合该资源。[发布者模型说明](https://huggingface.co/Snowflake/snowflake-arctic-embed-s) · [本次下载凭据](../research/paired_encoder_search_1127/arctic_publisher_receipt.json)

从 8,301 条课程训练题新划出 6,631 条供两组从头学习，另外 1,670 条单独评分，组间不共享标题。两组的程序、数据和预算相同，只改变资源目录。每组最多 22 次拟合、1,800 秒。新编码器的 11,546 段训练文本向量提前一次性算好，耗时约 156 秒。

| 资源目录 | 首轮可行动作 | 实际拟合 | Agent 最终选择 | 训练内留出 |
| --- | ---: | ---: | --- | ---: |
| 原目录 | 71 | 18 | MPNet 与 GTE-base 等权 | 1,222/1,670 |
| 多一个 Arctic | 72 | 18 | MPNet 与 GTE-base 等权 | 1,222/1,670 |

Arctic 在第二组首轮已可用，后续没有被提名训练。两组的 1,670 行预测逐字节一致，外部进程均成功重载。该结果衡量了把新模型提供给现有调度器的作用。Arctic 单用的分数和它能补对哪些题，需要另外的受控测量。[两组评分、训练次数与决策回执](../research/paired_encoder_search_1127/arctic_menu_results.json)

这两次运行冻结在修复本地编码器派生身份之前。它们都从 MPNet 提名案例投票，却实际试用了 MiniLM 表示。两次都保留原双模型，投票最终权重为 0。由这两组成绩无法判断正确的 MPNet 案例投票会怎样。合计实际拟合 36 次，模型 API 0 次。课程指定验证答案、正式测试与 H2 均未打开。
