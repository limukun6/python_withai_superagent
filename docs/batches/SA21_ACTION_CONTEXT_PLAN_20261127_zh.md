# SA21：让下一轮模型知道上一步实际做了什么

基线0b0f5c9。A修改recovery上下文投影与语义提示，不改B候选目录/排序。本批先计划、复跑代码，再检查与实跑。

## 瓶颈与实现

failed_actions只有提案SHA和诊断，不能让无会话记忆的下一请求看见上次的文件、键、列映射和输出选择。新增白名单结构投影action_summary，连同expected_check及原提案SHA保存；只保留文件/字段/解码器/指标/输出契约等参数，不复制行、数组值、模型生成的任意代码或自由文本。单摘要最多8192个UTF-8字节，明确记录截断；给LLM最多最近两份摘要，旧失败仍保留哈希和诊断。

在现有恢复循环中显式提示：摘要是上次失败动作，不是新证据；结合失败检查和原文修复，保留已有有效字段，不照抄错误动作。预算仍共享，结构工具最多2次、Flash最多3次/路径。

## 顺序与证据

1. 无fit/API检查：投影的内容和边界、30列映射、截断、去除rows/secret/代码、最近两条窗口、诊断与提案SHA绑定；用模拟错误提案→正确提案验证下一请求确实带上旧动作，不将其当真实模型改进。
2. 对已有真实失败回复做只读回放：选SA12留存的错误输出契约，记录原回复SHA和当前编译失败，生成摘要并核对检查。0fit/API，不改变旧回复，也不冒充新增真实LLM续答。
3. 冻结新来源开发输入，真实正式solve：C1为Breast Cancer公开数据的JSONL（训练/预测字段不同、预测字段顺序反转、保留原ID和显式概率类别）；C2为同一数据的NPZ/NPY键与结构接入。全部原文和oracle先固定，无manifest，无人工选择方法，最后新进程预测。每个条件只实跑一次，失败保留。它们算一个新来源、两个包装条件，不能说两个独立任务。

若真实模型第一次就给出正确契约，本批只能证明新来源完整接入和上下文兼容，不能宣称自然发生的提案修复收益。若自然提案失败，则逐项核对下一请求是否收到实际失败摘要，以及是否修复后交付；不为了制造好结果注入错误回复或重跑到成功。新来源是本轮开发输入，不是严格封存迁移或预测质量结果。
