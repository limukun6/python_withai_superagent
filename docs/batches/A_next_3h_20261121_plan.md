## 4. A-05：目标契约与不确定性，36 个案例

**瓶颈假设：** 输入中可推断的格式与必须声明的语义容易混在一起；默认值可能被误报成任务事实。

**结构：** 复用 `TaskSpec`/`MetricSpec`，优先补充可追踪的目标解析报告，不另造第二套任务 schema。逐字段记录声明值、实际观测、来源与 accepted/contradicted/unknown；将可运行性判断与未知字段分开。只有实际影响合法执行且不能安全确定的冲突阻止训练；未知本身不是一律拒绝的理由。不靠任务名路由、不从标签比例猜测正类、不让 LLM 覆写正式目标。

六类，每类 6 例，2 合法、2 冲突、2 信息不足，共 36 例：

| 类别 | 代表性问题 | 独立预期依据 |
|---|---|---|
| 类型/字段 | 声明单文本却含不兼容输入，训练和预测 schema 不一致 | manifest 与实际列/形状 |
| 标签/正类 | 非 0/1 标签、显式正类、正类不在训练域、二类/多类约束 | 预先给定标签域与任务规则 |
| 主指标 | 缺省来源、未知指标、macro-F1 与 accuracy 冲突 | 声明契约与手算例 |
| 文本对语义 | preference/symmetric/relation/未声明，实际增强含义 | 任务语义与执行变换，不用候选名称代替 |
| 证据身份 | trial/split/metric 错配、失败 trial、无测量 | 固定原始测量记录 |
| 交付契约 | 类别列顺序、预测行序、冻结后 schema 改变 | 原始行 ID 与冻结模型契约 |

每类 4 例开发、2 例预留，分别 24/12；分配轮换，三种状态在两个集合均有覆盖。预期标签先写文件，禁止被测检查器生成自己的答案。12 例只在修复冻结后运行一次；由同一开发者设计，明确称“预留模板检查”，不声称独立盲测或替代原96例协议。

**对照：** 当前提交上的行为 vs 最小修复后的行为；相同案例、依赖、schema。无缺口也如实报告当前通过，不为制造收益添加规则。
**指标：** 错误接受数/冲突总数、合法误拒数/合法总数、未知误确认数/未知总数、可判定覆盖率；按六类列分母，不能只报总通过率。
**晋级门槛：** 预登记冲突不得静默进入非法训练；合法接受率不得因修复下降；未知必须保留来源/状态。未支持的对称候选可明确拒绝，但不能称已支持对称任务。
**预算：** 完整训练 0、真实 API 0，运行时拦截 fit 的探针另计。保存 `A_05_plan.md` 与 `scripts/run_a05_task_contract_batch.py` 后再执行。

## 5. A-06：目标贯穿整条调用链

**瓶颈假设：** 入口声明正确，不代表搜索排序、复核、最终报告都用同一目标；分类概率列顺序也可能悄悄改变正类。

先冻结 12 条确定性轨迹：accuracy/macro_f1/binary_f1/roc_auc 四种目标 × 三种情形（合法、错指标/错正类冲突、缺失必要信息）。包含：

- 不平衡二分类，预设两个预测向量使 accuracy 和 macro-F1 的排名相反；核对选型是否跟随主指标。
- 字符串标签和显式正类，概率列置换以后按类标签对齐，AUC 应保持一致。
- 无显式正类时记录现有默认规则的来源，不能把默认当外部已确认含义；若课程协议有规定则以协议为准。
- 错误指标历史、缺分数、失败 trial 应拒绝比较或标记不可比较，不能拿 accuracy 兜成 F1/AUC。

轨迹经过 `TaskSpec → DecisionState → worker结果/ExperimentResult → 排序/confirmation → finalization报告` 的实际适用函数。各点记录目标哈希/名称/类序；不适用阶段必须显式说明。使用预设测量验证排序的部分是机制测试，不叫模型训练实验。

**对照：** 相同预测/状态下正确目标与受控错误目标；修复前后代码都跑同一协议。对正常路径的保护是主要约束，禁止用不同候选库制造差值。
**指标：** 目标漂移次数、错误排名次数、正确冲突拒绝数、合法路径受损数；各点均需可追溯。
**预算：** 核心完整训练 0、API 0；如必须用真训练复现则从7-fit备用额度中扣除，先更新协议。
**产物：** `A_06_plan.md`、`scripts/run_a06_objective_flow_batch.py`、12条逐阶段记录。

## 6. A-07：真实任务与图像端到端

**研究问题：** 更严格的目标/证据机制是否保持正常任务完成，是否已贯穿训练、预处理、导出与预测？

1. Dry Bean（数值、多类、accuracy）、SMS（文本、不平衡二类、macro-F1），各做基线/新版本一对，共4条路径。
2. 本机 sklearn 已带 `digits.csv.gz`，用 `load_digits` 转为真正的 N×8×8 图像输入，走 image adapter，再做1条新版本路径。它是低分辨率真实手写图像，不是自然图像泛化证据，也不作为后续封存 H 图像任务。

**控制：** 相同数据索引、种子707、模型种子42、候选全集、2次搜索、相同确认和重训；固定本地策略 interleaved_routes。基线代码用固定提交的独立快照，避免切换正在执行的工作树。每条预期2搜索+4额外确认+1refit=7实际分类器拟合，只选单分类器候选，开始前验证成本声明。

训练数据内先分出一次外层留出（预登记 seed=45101），其标签不进 planner 或用于选型；原包 validation/test 不作本轮开发选型输入。最终选择/refit冻结后评价外层一次。图像同样固定划分。任务包、划分、候选列表必须落盘指纹。后续模型变更不利用这批外层成绩挑赢家；其结果归开发兼容性证据。

**交付验收：** 无人工挑下一方法；按主指标自主选型；完整预处理与类别映射保存在模型中；新 Python 进程读模型预测同一输入，行数/行序/标签逐项一致，概率按类别列对齐；记录训练实际次数与全程耗时。
**结果：** 完成率、外层主指标与配对差、错误/超时数、重载一致率、fit与时间；不同任务分开报分数。合法路径应无新的目标漂移；分数改变需定位是预期修复还是回归，不能笼统称性能提升。
**预算：** 最多35 fits、API 0；每fit 60秒、每路径300秒共同墙钟上限（包括是否能约束确认/refit需先验证）。监控父进程对整路径设置硬超时；终止/失败成本记attempted或unknown，不虚报零。
**产物：** `A_07_plan.md`、`scripts/run_a07_delivery_batch.py`、图像构包函数、5条独立运行目录及汇总。
若95分钟时仍有目标错误，先只做图像+两个新版本路径（21 fits），旧版本配对推迟，明确证据降级为流程小试。
