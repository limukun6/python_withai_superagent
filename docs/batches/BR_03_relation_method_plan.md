# 在同一有序关系任务上让 Agent 决定要不要比较两段文字

目前五个候选把两列文本分别编码。先登记一个可用于一般有序文本关系的新候选，再读取 BR-02 的外层分数。该候选同时保留两列有区别的字符 TF-IDF 特征，并用已有共享哈希词与字符表示加入两段特征的绝对差、逐元素积。哈希每通道 32,768 桶，最后只拟合一个 C=1 的逻辑回归，最多 2,000 次迭代。不会按交换样本复制标签或假定反向关系。没有词典、类别专用规则、预训练下载或数据集名路由。

原菜单及已登记的 BR-02 路径作对照。实验组通过同一可信行号适配器与正式本地动态入口运行一次。新增方法仅在契约明确为有序关系、恰有两列文本时进入共同 AB 目录。保留原五项名称、次序、参数、首个候选和最终晋级规则。训练前逐项验证菜单，核对两个分支的公共代码、训练文件、实际行号及预算；将选择与复核交给 Agent，不保证它会选新方法。全程同一 CPU 环境，每组实际训练上限 11 次含重训，零模型 API。

原实验已经事先登记并完成训练。新模型封存后，两次独立导出相同的 754 行留出，报告两组准确率、macro-F1、差值、改对与改错数、实际训练次数、耗时，以及新方法何时尝试及是否最终保留。只做这一份预定划分。两组采用外层 157 个独立来源组和同一组隔离的训练内分区。课程验证、测试和 H 均不参与。
