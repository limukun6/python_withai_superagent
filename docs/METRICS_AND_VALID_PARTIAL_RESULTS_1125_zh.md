# 任务评分指标与中断交付验收

2026-11-25 在统一自主入口 `python -m unified_agent solve` 上验收。课程第 2 节说明各任务单独公布格式、划分和指标。第 5 节对 Released 和 Unseen 都计入有效的部分结果。本轮使用匿名合成数据，运行期间没有人工挑选模型。

## 评分指标确实能改变选择

在接入基线 `7894945` 上，旧数组读取入口把 README 的 `report macro F1` 退回准确率，开启声明读取的统一入口已经能认出这一句。任务清单里的 `F1`、`macro-f1`、`AUC`、`Accuracy` 当时都会被拒绝。

现在旧读取入口、任务清单、附带说明和自动文件适配使用同一套指标解释。清单优先，其次读取任务公告。只写 F1 时，二分类有明确正类或采用 0/1、false/true 的约定才使用二分类 F1。多分类需要明确平均方式。遇到已声明但有歧义、互相冲突或当前不支持的指标，停止按分数选模，记录原始原因。可独立确定训练类别和预测行时仍可交付类别预测。任务完全未声明指标时，保留默认准确率并在任务契约中将其来源标为未知。

给本地调度器相同的十行预测和相同的剩余预算，唯一改变的是评分指标。十行中有九行属于多数类。

| 预测方案 | 准确率 | 宏平均 F1 |
| --- | ---: | ---: |
| 全部预测为多数类 | **0.90** | 0.4737 |
| 识别出唯一的少数类，另有两个误报 | 0.80 | **0.6875** |

按准确率，调度器选第一组。按宏平均 F1，它选第二组。这项对照验证决策会随着目标改变。两组预测用于验收，数值不能作为 Released Task 成绩。

## 训练中断后能够交付什么

训练进程先根据训练标签保存类别比例。每获得一个更好的训练内主划分模型，就重新加载模型并比对逐行预测，再保存它的位置和文件摘要。正常结束时全量重训模型接替它。统一入口将训练和交付放在不同进程，能够在训练进程退出后检查已保存的文件，并从另一个进程生成预测。

| 匿名验收场景 | 最终使用的结果 | 实际拟合 | 交付行数 |
| --- | --- | ---: | ---: |
| 正常完成 | 全量重训模型 | 2 | 4 |
| 第一次训练开始前超时 | 训练类别比例，标记部分完成 | 0 | 4 |
| 全量重训失败 | 已验证的训练内模型，标记部分完成 | 1 | 4 |
| 已保存一次试验后训练进程突然退出 | 已验证的训练内模型，标记部分完成 | 1 | 4 |
| 模拟校园接口已发数据但在返回用量前断开 | 自动继续本地实验并完成重训，保留未知用量 | 2 | 4 |

五组在新进程重新预测，输出均逐字节一致。ROC-AUC 两组还核对了概率列和对应类别。另在完整模型的文件副本上损坏最终选择记录，能还原已验证试验模型；继续损坏该试验文件，能还原训练类别比例。两次各交付四行，额外拟合和 API 调用均为零。

用虚拟时钟模拟接口原计划持续 417 秒只发心跳的情况。在 1,200 秒总预算下，实验规划在模拟第 45 秒退出付费调用，未返回的用量保持未知。实际网络未用于此次故障注入。整机中断时，需要保留运行目录，再调用 `predict` 导出；连预测行、类别或输出契约都无法确定时，交付记录会说明哪些内容无法生成。能否得到课程部分分由实际评分器决定。

专项研究实际拟合 11 次，含修复前 1 次、五组验收 6 次、独立复核 4 次。专项真实 API 调用为 0。最终版全仓 746 项测试通过，用最终版重新加载四个故障场景、一个正常对照和上阶段真实 Flash 格式任务的模型，六份预测均与原文件逐字节一致。正式测试集与此前的模型排名均未用于这些检查。
