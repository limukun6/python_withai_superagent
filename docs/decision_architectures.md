# 决策架构与对照边界

v0.32 在统一 `superagent run` 入口接入三个可切换的决策流程：

| 参数 | 每个自适应步骤 | 最多模型请求 |
| --- | --- | --- |
| `single` | Planner 提方案 | 1 |
| `self_review` | 同一个 Planner 提方案后自检 | 2 |
| `reviewer` | Planner 提方案后由 Reviewer 审阅 | 2 |

三组首个实验相同，计入 `--trials`，不请求模型。之后每步最多执行一个实验。请求上限为 `(trials - 1) × 每步请求数`，同时受原有运行费用上限、持久任务账本和时间窗口约束。两次调用共用同一客户端、模型、账本和截止时间；不会自动增加费用额度、重试、递归讨论或另开执行工具。

选择 `--planner llm --architecture reviewer` 或 `--architecture self_review` 时，仍须提供原有模型、HTTPS 端点、密钥文件、已初始化预算账本、稳定任务 ID 和运行费用额度。完整命令的其它参数见主 README。默认本地模式不读取密钥；本地模式搭配审阅参数会在加载数据前报错。

三个流程的第一步 Planner 指令、证据投影和提案校验完全一致。第二步得到同一份冻结证据以及已校验的原提案。自检和 Reviewer 使用相同审阅规则、不同职责提示；它们都是无状态 API 请求，所谓“同一个 Planner”指角色提示和继承其原提案，不是隐藏的模型会话。不同实验运行的真实历史会随决策和训练耗时变化，不能声称各自后续上下文或实际 token 消耗完全相同。

Reviewer 只能返回 `keep` 或 `revise`，附上理由、最多四个已有事实引用，以及完整替代提案或 null。替代提案重新经过候选、过去引用、指标和参数契约校验。它不能删除历史和旧最佳、改任务目标、改候选参数、追加训练次数或指定最终模型。模型最终仍由共同确认流程选择。保留旧路线和回访条件由程序从全部真实历史重建。

审阅侧重三个问题：实验能否区分所提假设，是否忽略了值得继续的路线，是否把多项变化归因于单一因素。程序校验事实引用和结构，不证明自由文本解释或因果关系正确。Reviewer 可以保留一个合理的探索方案，不必机械地追随当前最高分。

审阅请求、计费或校验失败时，当前步骤保留已经合法的原方案，记录 `review_failed_original_retained`，关闭后续架构调用。后续若还有训练机会，由原控制器执行有明确标记的恢复流程。该运行的 `valid_policy_run` 和 `requested_planner_completed` 为 false；模型可用与架构完整分开报告。没有合法原提案的 Planner 失败不能借审阅重试。未知用量仍保留未知，不能按零记账。

`architecture_decisions.json` 保留每步原提案、审阅、最终提案、状态及证据哈希。原提案在第二次请求前先写入事件。`summary.json` / `run_outcome.json` 显示架构完整性和审阅回退次数。`ask_invocations` 包含在发送前被预算或时间挡住的调用意图，不能当作真实 HTTP 请求数；实际请求、token 和费用以原有请求事件、usage 和持久账本为准。

比较时 A 是低调用成本参照，B 与 C 用于检查角色提示是否优于同样增加一次自检。相同训练机会、调用上限不等于相同实际费用或实际耗时。应报告全部失败、训练数量、确认完成率、主指标、真实准确率、请求、token、费用和时间，不合成主观总分。正式无反馈对照仍需各自从头运行，不得遮盖已有反馈轨迹后冒充新盲实验。

本轮只有离线脚本与模拟传输验收，没有新的真实 LLM 比较、Released 分数或 API 消费。模拟 token 和费用只用于测试计费程序，不能计入真实课程账本。真实方案是否更好仍须在协议冻结后做小规模试跑，再考虑多种子比较。Task1 历史未知用量未解决前，继续禁止新增该任务的付费请求。
