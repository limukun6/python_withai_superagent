# Flash 详细错误反馈开发实验

2026-11-19。模型为 `DeepSeek-V4.1-Flash`，成功调用四次，新增模型拟合 22 次，用时 252.25 秒。按仓库课程价格表折算费用为 0.024481 元，学校账户实际扣费待核对。

## 设计与执行

沿用组合实验的两个文本开发划分 43111、43117，以及相同的前两步历史。每个划分分别让 Flash 接收配置和内部搜索总分，以及在相同输入上额外增加错误分组。两份上下文经程序核对，仅 error_slices 字段不同。两个划分交替请求顺序，每条请求独立提供历史。

两组动作空间相同，包含可用的静态 expanded 候选及四个预先指定的组合。已执行的前两步和共享第四步候选从第三步菜单排除。四个 API 决策全部保存后才开始训练。保持第四步候选和最终复核规则一致，每个完整路径逻辑预算仍为 11 次拟合。

本轮使用现有流式客户端，经直连访问学校 API。实验的 Session 将实际 requests 超时设为 60 秒。现有客户端的 llm_request 事件仍记录其原始超时元组 (10, 60)，实际覆盖值记录在本轮 protocol.json 中。HTTP 请求失败后脚本停止，无自动重试。

第一次在沙箱内执行时发生 DNS 解析失败，HTTP 请求尚未发出。该次记录保存在 runs/flash_error_feedback_v1，客户端按保守规则将其记为 unresolved_call。沙箱外只读 DNS 检查返回 10.121.10.250，随后经执行权限审批完成第二次批次，完整结果保存在 runs/flash_error_feedback_v2。成功批次四次响应均提供有效 token 用量和预期模型标识。

## 决策与训练结果

| 开发划分 | 只看总分的第三步 | 加错误分组的第三步 | 对应内部搜索准确率 | 反馈组目标 |
|---|---|---|---|---|
| 43111 | char_C3.0 | char_C0.3 | 63.8758% / 64.6284% | 高词语重叠组 |
| 43117 | char_C0.3 | char_C0.3 | 65.9454% / 65.9454% | 长文本组 |

43111 加入错误分组后选择了更强正则化的字符模型。相对第二步 char_C1.0，总准确率从 63.6877% 增至 64.6284%，但目标高重叠组准确率保持 58.4416%。Flash 声称的目标组改善没有发生。

43117 两个输入条件得到相同动作。相对第二步，总准确率从 64.4403% 增至 65.9454%，长文本组从 62.2172% 增至 63.3484%。因为两组动作相同，这次改善无法归因于额外错误分组。

| 开发划分 | 基线外层准确率 | Flash 总分组 | Flash 详细反馈组 | 最终候选 |
|---|---|---|---|---|
| 43111 | 66.7169% | 66.7169% | 66.7169% | word_char_stats_C0.3 |
| 43117 | 66.1643% | 66.1643% | 66.1643% | word_char_stats_C0.3 |

两个划分中，char_C0.3 均进入复核，但最终由共享第四步的组合特征模型胜出。同一划分三组外层预测逐项相同。43111 总分组直接复用原基线完整路径，43117 两个 Flash 分支共用同一完整路径，实际新增两个 11 拟合路径，共 22 次。

## 解释中发现的事实错误

43111 详细反馈回答将 char_C0.3 称为字符 n-gram SVM。代码中 `_char_difference_text` 实际构造的是 LogisticRegression。动作 ID 和执行配置通过验证，文字解释中的分类器类型仍出现错误。本轮候选菜单提供 ID 和参数，静态参数缺少分类器名称，这也是提示上下文的一个缺陷。

该回答关于“最邻近 C”的措辞也缺少明确距离定义，不能用它证明该动作更合适。后续应把实际分类器、表示、正则化方向等作为可核验字段随动作返回，并将假说中的目标指标和失败条件结构化。

## 本轮结论与后续结构工作

在这两个开发划分中，详细错误反馈使一次动作改变，最终模型和外层准确率持平。第一处目标组改善假说被实际预测否定。两个划分分别只请求一次每种条件，仍需新划分和重复决策评估稳定性。开发结果用于设计后续规则。

后续应首先连接三个环节。

1. 在动作菜单补齐代码可核验的分类器与特征事实，检查解释中是否与真实配置一致。
2. 将目标 slice_id、参照 trial、指标、预期方向和失败阈值写入结构化假说，试验后自动比较目标组与整体变化。像本轮“总分提高、目标组持平”的情况应撤销目标组改善假说。
3. 增加有明确特征机制的动作，例如局部对齐编辑特征。用现有目标诊断检验动作适用性，再比较固定动作与按证据选择动作。在新规则冻结后进行后续划分复验。

## 文件与复现

执行入口为 scripts/run_flash_error_feedback.py，需从仓库根目录运行，使用新的输出目录名。

```powershell
.\.venv\Scripts\python.exe scripts/run_flash_error_feedback.py --output runs/flash_error_feedback_v3
```

每次执行最多发送四条 API 请求，随后复用匹配的完整路径或训练新路径。遇到失败停止，已有结果目录保护覆盖。该命令会再次产生 API 用量。

本轮 protocol.json 保存脚本及执行源码哈希，llm_usage.jsonl 保存逐次 token 用量与课程计费。每个划分下的 prompt 和 answer 文件保存决策输入、输出。frozen_arms.json、results.json、outer_predictions.json 和 completion.json 保存冻结模型、评分和完成状态。决策请求记录在批次根目录，训练子目录中的 llm_calls 为零，因为训练阶段执行的是此前已冻结的 Flash 动作。
