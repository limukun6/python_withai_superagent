# A151 免费分析：选型本身损失多少

2026-11-24。0 次 API、0 次新训练。用 35 条已完成运行，比较"被选中的候选"与"实际探索过的候选里验证分数最高的那个"（两者都用各自 primary 划分的模型，训练行相同，只差选型）。

## 1 结果

| 项 | 值 |
|---|---|
| 运行数 | 35 |
| 选中了"探索过的最好候选" | **27 / 35 = 77%** |
| 未选中 | 8 / 35 = 23% |
| 平均选型损失 | **+0.15pp** |
| 最大损失 | +0.745pp |
| 损失 > 1pp 的运行 | **0** |

| 运行 | 选中 | 实际更好 | 差 |
|---|---|---|---:|

| `w1_numeric` | `numeric_tabular_logistic_C0.1`（0.9232） | `numeric_tabular_extra_trees_leaf1`（0.9258） | 0.257pp |

## 2 读法

1. **选型不是主要瓶颈**：77% 的运行选中了探索过的最好候选，最大损失 0.745pp，没有一次超过 1pp。
2. **损失的大头在探索**：结合"目录首项 vs 选中"的免费分析（单文本 +31~+42pp、类别表格 +6.4pp），可见真正决定结果的是"有没有试到对的候选"，而不是"在试过的里面选谁"。
3. **选型噪声是真实存在的**：调度按 primary 划分的分数选，而验证集可能给出相反顺序，23% 的运行就是这种情况。差都不大（<0.8pp），但方向与"用哪个划分做决策"直接相关。

## 3 边界

- 每轮只探索 **2 个候选**（fit 上限 3、预留 refit），所以"从 2 个里选最好"是很弱的检验：随机也有 50% 命中。
- 因此 77% 不能当成"选型很强"的证据，只能说"没有观察到大的选型损失"。
- 本文用的是任务的官方验证集打分，而调度用的是 primary 划分；两者不同正是第 3 条的来源，但也意味着这不是"同一指标上的自评"。
- 与所有 A151 单次对照一样，受 7.9pp 漂移约束；这里比较的是**同一次运行内部**的两个模型，漂移影响小得多，但仍不是零。
