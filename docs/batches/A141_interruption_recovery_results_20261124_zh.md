# A141：关机后已有成果可显式恢复交付，9项受控验收通过

瓶颈：原partial_delivery只在程序捕获异常后运行；强制关机可能跳过处理分支，重启后没有独立入口使用已完成成果。对应结构是`tools/recover_run_checkpoint.py`：只读旧目录，在另一个新目录恢复可预测模型；核验原训练源码全部SHA、训练包SHA、任务/指标/类序、内部划分、标签/预测及完成fit凭据。没有重发API、继续搜索或重训功能。

若尚未形成最终模型，沿原freeze_checkpoint保留已核实的最好primary模型并标partial，不冒充全量重训；若已有最终封存模型，则保留原refit状态并重新交付。最新state截断可退至前一个完整快照，明确列出跳过项；已解析但目标/证据矛盾会拒绝。原已完成/在途worker凭据全部列入资源继承说明，不能把无usage当零或重置剩余预算。

先登记计划、代码与0fit/0API预算，再复用A138已训练组件构造磁盘状态。它们是工程注入，不是真的给电脑断电，也不算新增任务：

| 案例 | 实际结果 |
|---|---|
| 第一个试验后中断 | 恢复已训模型，partial，独立预测一致 |
| 全量重训前中断 | 恢复已核验较优checkpoint，partial，不重训 |
| 下一worker只有admission | 可交付旧模型，同时保留在途fit用量unknown，不承诺安全续训 |
| 最新state写到一半 | 退回前一完整state，记录state_3.json被跳过 |
| 最优checkpoint模型损坏 | 拒绝，无伪成功模型 |
| 训练包SHA错误 | 拒绝，未读错误包的训练内容 |
| 完整模型已有、CSV写到一半 | 保留完整模型状态，重导出32行，与原成功结果一致 |
| 同一只读目录恢复两次 | 预测一致，原目录所有根文件SHA未变 |
| 错误源码版本 | 拒绝，要求原训练93源 |

所有成功恢复均完成native/隔离源码包32行预测逐字节核对，原完整模型、训练证据、94个生产源码和真实372账本均未改。恢复工具运行在确切原训练93源上，新工具放tools，不把旧模型重标成新训练。累计仍1614fit，本批0新fit/API/费用。

边界：没有保证任意断电位置、文件系统损坏或丢失全部checkpoint仍可恢复；原目录中没有完整证据时会拒绝。工具恢复的是模型交付，不会继续原实验队列；partial未完整重训的事实保留。若以后要支持续训/继续搜索，需要另做动作幂等、在途worker及共享API账本对账协议，不能直接将本工具当resume开关。

复跑runner：scripts/run_a141_interruption_recovery.py；元数据research/a141_interruption_recovery。恢复示例：

