# 把旧模型训练得更充分，再复核第三成员是否仍有帮助

两套五折的概率提名分别净增 32 和 4 题。第一个问题是 Agent 在小训练集上判断第三成员的价值，交付时两个参考模型也已得到更多数据。事先固定一个额外复核动作，直接检验数据规模带来的变化。登记时还未在下面的中等规模划分上拟合参考头，也未查看相应的预测或收益。

控制为同折已封存的 `pilot-brier`。仅当原 Agent 已批准第三模型时，新增两次拟合。把该折原试用区和提名区合并，用同样的方法、固定权重和参数重训两个参考头。第三成员继续使用原试用分类头在复核区产出的概率，复核区从未参与这三个头的拟合。按原来的等权投票重新计算复核区净改对和概率误差改善，使用原来相同的批准门槛。只有新复核也通过才保留原三成员交付，否则交付同折全量训练的两个参考成员。已经退回双模型的路径无需额外拟合。这个设计刻意让第三个成员面对更强的参考头；它检验在这种条件下增加一次确认是否有用。

普通入口实际生成的试用、提名与最终模型按任务包、行序及模型哈希复用。每条从空缓存独立执行，最多六个试用头、两个扩大训练量的参考头和三个最终头，共十一；在这次有原件的配对开发研究中两套各有四条已批准路径，共新增十六次本地分类器拟合。零模型 API，不改划分、候选、阈值和融合权重。先封存两套全部决定和逐行输出再评分。若一次复核撤回原选择，用原始无标签文本在新进程实测新的两成员交付；其余路径逐行核对既有原生导出。报告同折新旧参考各自在复核区的准确率、第三成员相对两种参考的收益，以及规则在外层相对原 Agent 的改对、改错和组配对区间。同时要求两套划分相对原 Agent 净增、至少一套区间下限为正，才值得放进默认决策。该配对研究复用开发样本，独立外部任务仍依其先前的门槛封存。
