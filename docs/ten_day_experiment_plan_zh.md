# General Algorithm SuperAgent 十天实验与交付计划

以两名成员、一台 RTX 5070 8 GB 电脑、十个自然日排期。表中的人时是两人合计，按每人每天约 3 小时估计，共约 60 人时。已发布任务的主线可以在 CPU 完成。以整合提交 `e472a58` 为开发起点，已有实验的数字用于选题和估时。正式报告结果须能由同一最终提交版本自主生成。D1 为开始执行的当天，提交时间按本班课表核对。

## 1. 全部 13 项瓶颈与整合进度

**增加一项零 API 的机制实验，与准确率消融并行。** D3–D4 由成员 B 准备 6 类各一正一反、共 12 个案例，涵盖任务语义、工具配置、证据引用、gap 与主指标冲突、多因素归因、记忆撤销。成员 A 在看预期答案前冻结程序规则。把同一输入交给“仅检查 ID/格式”和“启用已有事实/证据检查”两种离线处理，按类报告错误拦截数/错误例数和合法误拒数/合法例数。尚无对应校验时标记“未覆盖”。自由文本的语义冲突由两人按事前答案独立标注，有分歧保留原文。合成案例衡量程序能否拦错，真实历史轨迹另列；这项实验不能估计模型在新任务上犯错的频率。

案例整理与核对预计 3–4 人时、机器 5–15 分钟，取自 D4–D5 原分配给条件实验 C 的 5–8 人时。若 C 无触发或排期紧张，优先完成该离线实验；若 C 有触发，在剩余工时内只验证一次干预。D6、D8 的恢复与验收案例复用原排期。这样任务理解、推理错误、记忆和交付均有验收，正式训练批数与 API 上沿仍按第 3 节。

## 2. 结构改动与可证伪的预期

**优先实现一个预算分配开关。** 复用 `benchmark.run_one` 的搜索、`local_search.LocalSearchPolicy` 的 interleaved_routes、`confirmation.confirm_candidates` 的三划分评分和现有最终重训。仅把 4 个搜索名额、前三名晋级变成 6 个搜索名额、前两名晋级。两组从同一候选开始，搜索前四步应逐项重合。继续用三划分平均主指标择优，同分按既有规则。表格与文本共享控制逻辑。这样能将“多探索”与“换模型家族、改训练器、改提示词”拆开验证。若现有策略第 5、6 步仍集中在同族，记录下来，第一轮保留现状以便归因。

**第二优先级是只允许 Flash 改一次决策。** 本地策略在完整预算内独立给出默认下一项。在已完成四项探索、还有扩展名额、最近两次都未提升最佳搜索分数，且目录还有未探索算法路线时，允许 Flash 为第五项提一个不同路线的合法候选。第六项恢复本地策略，接收第五项的真实结果。每轨迹最多一次调用。与完全本地的 6/2 方案同预算配对。若开发轨迹从未触发，记录触发率，结束这一支，避免为两个任务反复调阈值。

伪代码中的“路线”复用已有 route_of，“改正/新增错误”复用 prediction_evidence 的同划分逐行比对。正式任务若主指标为 F1 或 AUC，晋级按任务主指标，准确率净改正数只作辅助解释。

```text
读取训练数据、任务声明、优化方向与候选库
固定外层训练与留出索引，规划器只能读取外层训练中的搜索观测
for 每个探索名额:
    默认候选 = 本地策略(可选目录, 已完成历史)
    if 启用单次 Flash 且触发条件成立:
        提供合法的未探索路线、标量分数和剩余预算
        要求输出候选 ID、参照候选、对主指标的方向预测
        校验 ID 可用、路线不同、参照已测、预算足够
        对失败登记原始错误和费用状态，终止该实验臂
    在同一搜索划分拟合候选，记录主指标、路线、参照和预测是否兑现
取前 K 名，在另外两个共同划分复核；按三划分均分选模型
在全部外层训练行重训并冻结；随后评估外层留出并保存逐行结果
```

**把模型常犯的错误变成可观察事件。** 在 `benchmark.py` 决策日志中加默认候选、实际候选、触发理由、参照模型、预期方向和实测方向。复用 `contracts.py` 和现有配置校验，拦截不存在的候选、重复尝试和引用未完成的试验。沿用 `prediction_evidence.py` 统计新候选改正了哪些样本、又引入了多少错误。记录“有效 ID 的提案比例”“触发后改变决策比例”“跨路线提案经复核获胜比例”“预期方向命中数/可判断数”。小样本附原始计数；相同路线的合理调参不能一概计为错误。学生可以在运行后解释现象，运行期间的下一步由程序决定。

**预留方向。** 队友已有候选组合、挑战者和资源分配的原型。只有在扩展搜索确实找到更好的候选，且剩余工期足够时，才考虑用白名单组合产生一个新配置。它须占用相同的第 5 或第 6 个名额，先经 schema、构造和输入输出形状校验。十天主线交付不依赖该项，也不依赖训练新神经网络。

## 3. 实验顺序与停止规则

共同条件为同任务同外层索引、同内层种子 707、同候选池、同起点、同缓存规则、同训练器和重训过程。主要实验每臂限 11 次分类器拟合、600 秒总预算、单次训练 90 秒。记录实际分类器次数与超时，固定总时限是实现的运行预算，SSE 和子进程收尾可有尾差。允许实验臂使用不同次数的 API，单列费用和等待时间。实验期间串行占用同一台训练机；不同种子轮换运行顺序。对未形成完整模型的轨迹报告失败及原因，准确率报告同时给出有效配对数和计划数。

| 阶段 | 设计与新增资源 | 要回答的问题及决策 |
|---|---|---|
| A．整合试点 | 两任务 × 已冻结开发 seed 42011，复用两条 fixed。只新增两条 scalar-feedback，每条 4/3、11 拟合、3 次 Flash。保留原试点源码与环境跑完 | 扩展目录中，逐轮反馈能否改变候选路径、改正固定组错误？列 2 个配对、净改正数和成本。小试点不单独决定提交方案 |
| B．本地预算消融，主实验 | 两任务 × 开发 seeds 42011、42017。比较 4/3 与 6/2，共 8 条、最多 88 拟合、0 API。42011 的两条 fixed 若索引、环境、实现和控制路径等价且有指纹，可复用作开发分析。为 4/2 中间组仅从 4/3 的已有三个划分中取前两名，若选型不同则按同协议补完整重训，最多再加 4 次 | 4/2 减 4/3 测少复核一名的影响；6/2 减 4/2 测增搜两项的影响。验证前四步逐项一致。记录第 5/6 项进入前二、最终胜出及其外层收益。缺少实际观测的反事实记为缺失 |
| C．单次 Flash，条件实验 | 只有 B 的开发轨迹出现预设触发点，且账本可用才做。两任务 × 同两个开发种子，共 4 条新臂、最多 44 拟合和 4 次调用。无触发且路径完全相同的轨迹在开发分析中可精确重放并标识 | 与 B 的 6/2 比较，检查同一第五步的本地默认和 Flash 提案是否不同。只对两边实际运行过的候选比较分数。若四个配对均同选且同预测，停止扩展 |
| D．冻结后独立复验 | D6 前写入清单的三个新开发分区种子 42041、42053、42067。每任务比较 fixed 与一个晋级方案，2 × 3 × 2 = 12 条、最多 132 拟合。如果仅本地方案晋级则 0 API，单次 Flash 方案最多 6 次。如 A 的逐轮方案晋级，最多 18 次。若开发阶段无方案达门槛，保留 fixed，跳过无意义的重复对照 | 每任务单列三个配对差值、胜平负、逐行改正/新增错误、拟合/调用和秒数。不同种子使用同一任务的重叠数据，不作独立任务上的显著性声明 |
| E．通用性与提交 | 两个匿名冒烟包，覆盖数值多分类及小图像多分类；至少一个使用 macro-F1。另测无验证集、未知类别或列顺序变化中适用于声明 schema 的情况。两个发布任务用冻结提交和同一自动策略从头跑，按任务规定的 split/metric 出结果 | 跨模态检验入口、分组隔离、预算、模型重载、预测行数、类别与概率列顺序。官方 test 仅在任务规定的最终评估阶段使用。冒烟包分数不作为未见任务性能结论 |

这里 4/3、6/2 指“搜索候选数 / 晋级复核数”，包括第一次搜索划分在内每个晋级候选共有三次测量。固定组本身会根据已有观测选择下一候选。

按资源上沿合计，A–D 连同两个可选开发分支最多新增 312 次拟合、34 次 Flash 调用。这个数用于预留资源。优先路线为 A → B → 本地挑战者的 D，开发控制组可完全复用时，按 22 + 66 + 至多 4 + 132 计，最多 224 次新增拟合、6 次调用；若 B 初筛不通过则进一步缩减。E 阶段单列，两次正式发布运行各按最终配置计费。保存每次实验的任务和 seed、源码和模型指纹、实际耗时、调用与训练次数，据此更新剩余预算。

**预先约定晋级口径。** 以下是项目决策阈值。开发筛选要求两个任务均有完整有效配对，两个任务均值均不比 fixed 低超过 0.2 个百分点，且至少一个任务均值提高 0.2 个百分点，或两个任务均保持在上述容差内且中位墙钟时间缩短至少 20%。A 只有一个开发种子，若它独有明显优势，先补 seed 42017 的两个 4/3 Flash 臂，再用相同规则筛选，新增最多 22 拟合、6 次调用。多方案过线时按两任务等权平均差值、模型调用数、总耗时依次决定唯一挑战者。D 阶段沿用同一效益标准，另要求有准确率收益的任务至少 2/3 种子优于 fixed，效率路线则至少 2/3 种子更快。任一任务出现超过 1 个百分点的单种子损失，报告该案例并保留 fixed 为稳妥默认。测试完成率单列，任一候选对同一任务不能自主完成则不晋级。若都未过线，结论可以是固定的多轮本地策略目前最可靠。

## 4. 墙钟时间、调用和人力

本机 11 次拟合的 fixed 表格为 120.2 秒，文本为 58.7 秒。历史 E1 的 40 次标量反馈 SSE 调用中位 17.5 秒，P90 为 34.2 秒，最长 97.2 秒，包含生成和传输；60 秒是单次读取无数据的超时。以新试点两任务为例，计算约 179 秒，加 6 次调用的中位等待约 105 秒，中心估计约 4.7 分钟。不改训练组合时，把每次等待换成 P90 约 6.4 分钟；它不是整批 P90。候选的计算成本会变，尤其是树深、字符特征和完整重训。E1 表格 F 也实际出现过单轨迹约 16 分钟，因此给新批次留足排程余量。

## 6. 报告中的实验结论怎样写

每项写清“改变哪个决策、控制哪些条件、哪些预测因此变化、花了多少资源、证据覆盖几组”。核心表以任务和外层种子为行，记录两臂准确率、差值（百分点）、改正/新增错误、拟合、API 次数、token、课程费用、墙钟秒数和失败。附一张搜索轨迹图展示哪一步探索到了最终候选，一张三划分配对图解释何时换模有根据。官方发布指标和训练内留出结果各自注明分母及划分来源。

若 6/2 胜且 4/2 与 4/3 接近，可把开发证据解释为额外探索带来收益；若 6/2 的候选搜索分数上升而外层下降，说明这套筛选未能把内层优势转成泛化收益；若 Flash 改了路径却产生相同预测，则直接报告它在这些轨迹上的额外时间和费用。每种结果都能回答架构选择问题。通用性只陈述实际运行过的模态和指标，真正未见任务留待课程冻结后评估。
