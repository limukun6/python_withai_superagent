# SA19：失败后继续执行的首批实现与验收

基线0769d22；本批A修改semantic_contract、autonomous_run中状态传递及新增recovery/structure_tools，不改B的方法排序规则。先落盘本计划和复跑脚本，再实跑。

## 瓶颈与改动

1. 接入只容许两次失败提案：改为共享原请求预算内的恢复循环；失败、已查事实、未决项、可用动作与剩余资源持久化。同一错误重复不新增事实，明确反馈，不伪称成功。
2. 数组/图像结构无法查证：补数组键、shape、dtype以及图像尺寸/模式工具，只向模型提供元数据，不提供行值/像素/预测答案。
3. 接入与选模各自孤立：同一恢复状态接入正式_train，保留B已有失败换候选逻辑，给后续规划传失败原因；有效模型和预算照旧保留。

## 顺序与预算

先0fit/0API结构与回归；测试脚本scripts/run_sa19_recovery_checks.py。之后scripts/run_sa19_recovery_live.py先prepare冻结输入和oracle，再run独立正式入口路径。原16条未知保持null；共用真实累计账本，新增unknown/pending立即停当批付费且不重试。

预登记案例：R1 Wine开发数据的训练/预测字段不同；R2同一Wine的未知NPZ键；R3同一Wine路径的首个选中方法在启动前出现受控依赖故障；R4两列潜在目标、说明确实没指定目标。R1/R2需自然LLM查证，不注入回复或选择。R3只在启动前注入一次RuntimeError，实际fit仍由正式执行器完成并记账；这是故障恢复集成检查，不把B既有能力说成A新增收益。R4不应完整完成错误目标。

每条最多4次实际fit（含refit）、3次Flash、360秒；四条总上限16fit/12API，估计停止阈值每条¥0.30、合计¥1.20，不保证学校最终扣费。失败请求不自动重试。允许已计量语义修复在同一预算内继续。prepare/run/audit使用新目录，保留失败记录。

## 验收

主指标是经历失败后正确完整交付、错误完成、人工介入及资源。用冻结oracle核对目标/指标/输入结构与输出格式；成功路径另起进程predict，核对行序和预测一致。R1/R2旧本地读取不训练的结果另记为接入对照；不当作随机性能消融。R4记未决交付，不并入可恢复成功率。不同包装不算独立任务，Wine为本轮新来源开发数据，不宣称未见迁移成绩。

若真实路径失败，先分析已结算回复和新事实；后续修复新批运行，不能覆盖/重试同scope。完整后写报告、状态、实际fit/API/费用/耗时并提交代码与脱敏证据。完整输出后运行时的任意异常恢复和任意未知任务保证仍不在首批证明范围。
