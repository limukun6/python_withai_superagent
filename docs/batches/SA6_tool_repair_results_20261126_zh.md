## 瓶颈与对应结构

1. **逻辑角色不等于物理包。** `source=prediction`现在表达预测角色：实际给了外部预测包就只查该包，否则查同一个任务包。返回`package_source`记录实际来源，避免P2因同包预测被误拒绝。外部包缺成员仍报错，不跨回训练包寻找同名文件。
2. **扁平数据不存在命名集合。** 若CSV或根JSON列表的探查请求带了泛称，工具返回实际字段、null collection，并记录原值与归一化依据。不是伪造存在的表。带命名键的JSON、SQLite或工作簿不走这种回退，不会用另一张表替代指定集合。
3. **解码器的位置字段要按格式解释。** 原decoder对CSV返回的location是分隔符`,`，对SQLite等才是集合位置。原工具把两者统一称collection，会把正确解码结果再误报给模型。现在分开返回delimiter与collection。这是程序接口错误，不归咎于模型思考。
4. 真实引用、已知验证/答案成员和集合的拒绝仍保留在读取之前；工具只返回结构，不回传行值。生成的最终任务契约仍须实际编译和预检，探查成功不代表目标正确。
