## 谁决定用什么模型

开发时准备通用工具和验证规则。正式运行只接收任务、可用资源、预算。它读取训练说明、根据任务结构组装合法方法、生成新的分类器配置，按已经观测到的分数决定下一步。在默认组的 67 个初始可选动作中，实际先后训练了 MiniLM、ELECTRA、BGE、一棵临时生成的树、E5、GTE 和词字符特征等。三组从头运行产生完全相同的 940 行预测，GTE 相比上一交接版改对 53 条，也改错 50 条。每一步日志记录当时可见的实验编号，最后的选择与重训文件绑定。[决策与工件校验](../scripts/summarize_encoder_experiments.py)

普通运行使用 `python -m unified_agent solve`。在有足够训练机会时，可以给同一入口设置 `--feedback-reflection matched-finalists --fit-limit 20`。这个模式先按逐行训练预测找出值得比较的单模型或组合，然后让它们在相同的独立训练划分上比较。Task2 在三份划分上都支持 GTE-small 的线性头。另一份匿名十分类开发图像任务中，Agent 选择梯度方向直方图、运行时生成的梯度提升树和随机森林的三模型融合。三份训练内划分合计 660 行，最佳单模型答对 527 行，融合答对 550 行（79.85% 和 83.33%）。全量重训后交付 350 行预测，未读取这 350 行的答案。这个实验验证了选择会随任务和反馈改变。[融合机制](../superagent/finalist_race.py) · [图像实验](../research/paired_encoder_search_1127/image_results.json)

## 后续实验可以直接复用什么

在固定的三份训练内划分上，GTE-small 比原交接方法分别多答对 5、25、22 条。又试了不同编码器、上下文交互、词级注意力、联合编码、特征融合、由反馈生成的正则强度和低秩微调。GTE-small 与 GTE-base 的等权融合比 GTE-small 分别多答对 10、19、13 条。GTE-base 单独使用时在第二份划分少答对 4 条。此结果支持把 GTE-base 加入可用工具，后续从原包运行仍须由 Agent 自行选择。[分阶段训练结果](../research/paired_encoder_search_1127/) · [编码器宽度对照](../research/paired_encoder_search_1127/scale_results.json)

这批工作有 61 次 Task2 冷启动实际拟合、5 次补齐对照、24 次训练内研发拟合及 12 次匿名图像拟合，共记录 102 次。新增模型 API 请求、用量和费用均为零。交接压缩包包含实际拟合的模型、GTE-small 权重、统一源码、运行记录与预测。已换目录、移除外部权重路径、禁网重载并逐行复现 940 条预测。仓库只收录源码和脱敏回执。[可移植包校验](../research/paired_encoder_search_1127/portable_receipt.json) · [原包实验入口](../scripts/run_paired_encoder_entry.py)
