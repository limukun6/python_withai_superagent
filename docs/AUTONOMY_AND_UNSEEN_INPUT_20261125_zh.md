# 自主决策与陌生输入验收

## 同一入口如何做决定

课程要求所有已发布任务和未见任务共用同一个 Agent。训练阶段依据任务目标、数据和历史实验做选择，开跑后由程序决定下一步与最终模型。只给任务包改名、保持数据、声明和预算一致时，本地规划器的选择应一致。

旧整合版 `e85d8b9` 已能读取训练反馈，但类别表格开场固定比较两种树深，成对偏好文本开场使用专门配置的候选目录和试验次序。新入口只把可运行工具、训练划分、评分目标和资源交给规划器。它根据输入特征、样本数、已观察到的分数、训练与留出分数的差距，估计下一次探索或复核是否值得。两种模型在相同行上的概率可以组成候选。融合要在不同训练分区取得配对支持，并为两个成员的最终重训留下预算。

本地规划器使用人编写的通用规则。它能从已安装的分类器生成配置，在兼容任务上选择已登记的特征方法。候选工具、支持的评分指标、预算上限和证据门槛是软件设计的一部分。默认运行从第一步到封存模型没有人工选择。另有受累计账本和模型白名单约束的 DeepSeek 规划接口，本次核验使用本地规划器。

| 输入与评价范围 | 独立运行选出的模型 | 答对题数 | 准确率 | 实际拟合，含重训 |
| --- | --- | ---: | ---: | ---: |
| Task1，课程指定验证 | 用训练数据选类别字段交互的 CatBoost | 1,533 / 2,030 | 75.52% | 10 |
| Task2，课程指定验证 | MiniLM-L12 加训练语料熟悉度特征的分类器 | 684 / 940 | 72.77% | 10 |
| Wine，匿名三分类数值表，开发留出 | 运行时生成的随机森林 | 45 / 45 | 100.00% | 7 |
| Digits，匿名十分类图像，开发留出 | 梯度直方图和像素分类器的等权融合 | 445 / 450 | 98.89% | 10 |

原整合版两项指定验证为 1,532 / 2,030 和 689 / 940。本次 Task1 多答对 1 题，Task2 少答对 5 题。Task2 新路径探索了 9 个配置后将最后一次拟合用于重训，未获得复核融合的证据。两版同时改变了搜索策略和最终训练数据的取法，单靠这次对照无法把 5 题之差归因于某一个改动。旧版交付包独立保留，两项课程成绩始终按同一运行版本列示。

把匿名数值表改成暗示“标题任务”的包名、同时更换特征列名和标签列名，10 个决策和全部预测保持一致。四个任务的 36 次原始决策均可重放，颠倒候选的展示顺序得到相同动作。保持候选、预算和行顺序不动，交换两个已在相同分区测过的模型的整份反馈，219 次反事实回放中有 103 次改变了下一步。此项衡量规划器对反馈的敏感性，不用于宣称性能收益。

四个任务共保存 36 次运行时决策。交换两个模型在相同训练分区上的完整反馈、保持候选与预算固定，219 次反事实交换中有 103 次改变下一步。反转菜单显示顺序的 36 次重放均保留原动作。交换结果说明决策确实使用反馈；多个交换取自同一运行，不能用作独立样本的统计检验。另一次真实冷启动把数值任务改名为标题任务并替换特征和标签列名，10 步动作及预测文件完全一致。

## 陌生封装的实际故障

标准目录 `train/类别/图片`、有明确标签的普通训练 CSV、NPY 和 NPZ 已有读取能力。原入口在 TSV、Parquet、部分目录命名、特征损坏但标签仍可用等场景会中止。共用一张表而只凭输入名 `train.csv` 把整表当训练集，还可能将验证和测试行混入学习。

正式入口现在可以接收 ZIP、目录、独立表格文件。它能从明确的目标列、指标、文件名和行划分声明建立输入契约。受支持的表格包括 CSV、TSV 和标量列 Parquet。图片测试覆盖划分在外层和类别在外层的 PNG/JPEG 目录。对同一张表，先选择指定划分的行，再做特征类型判断、类频率统计和训练。训练及预测分别投影所需的列。CSV/Parquet 可能物理同文件，行隔离的实证是改变留出行的标签和类型后，交给训练器的样本、标签和分布仍然正确。

| 验收输入 | 正式入口观察结果 |
| --- | --- |
| 普通 CSV、manifest CSV、README 声明非标准文件名的 CSV、TSV、Parquet、NPZ | 完成搜索、重训、预测和独立进程重载 |
| 同表划分、匿名成对偏好文本、两种图片目录结构 | 完成训练和预测，保留声明的指标和输入行序 |
| 特征列全空且有真实训练标签、训练特征文件缺失且另有明确训练标签文件 | 从可信训练标签冻结类别频率，两次独立预测一致，运行和交付都标为 `partial` |
| 缺少可确认的目标列和类别来源 | 生成原因记录，状态为 `unavailable`，没有生成猜测标签的预测文件 |

13 个场景共 92 次实际分类器拟合，规划模型 API 调用为 0。两个保底场景和无法交付的场景均为 0 次拟合。此处衡量数据能否被正确接收和交付；匿名小样本的成绩不代表未见任务成绩。保底输出按训练类频率计算，只有训练域和预测行能核对时才会生成。课程对有效部分结果给出的评分条款没有承诺某个保底模型一定得分。

## 如何重验

`python -m scripts.accept_input_formats NEW_DIRECTORY` 会锁定代码摘要、构造合成输入、禁止联网，用正式入口运行并在独立进程重新预测。每种输入保留读取成员、实际拟合次数、预测行数及模型和预测摘要。单元回归可用 `python -m unittest tests.test_format_delivery tests.test_anonymous_policy` 运行。

课程包的四个自主运行用 `scripts.verify_anonymous_planner` 的 `prepare`、`train`、`score` 三个阶段复核。先封存全部模型，再由独立进程作两次完全相同的预测，最后核对指定验证答案。正式测试集留给最终评价。每份任务目录下的 `run/agent/decisions.json` 记录实际动作、当时可行的其它选择、训练与重训预算。`history.json` 和对应逐行预测可独立重算分数。

完整回归通过 716 项。复核过程中修正了两处测试记录，一处将读取监控限定到真实原始包，另一处为旧的“分数下降”测试补齐同一划分的身份，并保留身份缺失时不可比较的断言。[脱敏验收记录与摘要](../research/anonymous_input_1125/verification.json)
