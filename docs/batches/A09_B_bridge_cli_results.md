# A-09：正式入口接通 B 调度（2026-11-21）

## 瓶颈 → 结构 → 证据

**原来的瓶颈：方法和调度各自能跑，但正式入口还不能把它们串起来。** 已将 B 的 a787a28 快进合入 codex/expanded-feedback，在正式 `superagent run` 增加 `--scheduler ab-v1 --portfolio ab-v1`。A 入口生成 TaskSpec、训练内三划分和逐行证据，B 选择 explore/confirm/stop，A 校验并执行，最后按共同配对规则重训和导出。不调用研究脚本来替正式入口选方法。

**资源瓶颈：一次“尝试”不等于一次实际分类器训练。** 原 B 验收脚本的守卫没有默认进入生产 worker。本批在 worker 的每个已注册分类器 fit 前写入尝试次数并检查限额，成功后记完成次数；控制器与返回结果逐次对账。当前闭合目录覆盖 LogisticRegression、ExtraTrees、SVC、CatBoost；树集成算一个分类器，其内部树不重复算候选。这个守卫不是任意生成代码的沙箱，也没有自动支持未知训练框架。

**实验：一个匿名合成数值任务，正式 CLI 全自主运行。** 256 行训练、31 行无标签查询；与 B 同生成配置/种子但环境不同，实际划分指纹不同。运行中 5 次探索、4 次复核、1 次停止，最后 1 次完整重训，共 **10 次真实 fit**。训练路径 **18.791 秒**；首次验收器总耗时 **20.578 秒**。原始目录 `D:/codex/python_withai/runs/a09_bridge_cli_01`。

可解释轨迹：第 8 次试验的 SVM 在 primary 得分 0.7843，高于树的 0.7647；但在共同 confirmation_1 上二者同为 0.7059，未满足“两次严格胜出”的替换条件。调度保留树模型。这里只说明系统确实使用复核证据，不能证明保留树在外部数据上更好。没有外部测试成绩，也不因 primary 分数最高就改规则。

**交付验收：两个新进程分别从原目录与迁移目录调用正式 predict。** 31 行行序、预测标签与 CSV 摘要相同，验证耗时 **3.754 秒**、新增 **0 fits**，复用上述已训练的 10 fits。目录 `runs/a09_bridge_cli_verified`。生产源码指纹在训练和重新验收之间未变。
