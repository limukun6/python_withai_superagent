# SA26：任务规则解释失败后继续恢复

基线91f1a8c；A负责任务解释、声明来源、恢复入口和缓存，B方法/排序不改。先保存本计划与可复跑脚本，再运行。

## 瓶颈与实现

当前proactive/auto遇到RestrictionError、DeclarationError、MetricDeclarationError时直接退出；即使LLM已能编译数据，bind_semantic_rules也会重新遇到相同措辞而反复失败。显式manifest不能替换整个输入契约，但其中依赖原文的未识别措辞需要可恢复。

增加数据式semantic-rules-v1外层：interpretation保留既有task/native/output协议，rules仅允许对真实原文中未被确定解析的method_restrictions或metric提出受支持解释，并给逐字引文、真实文档引用和值/理由。用调用局部上下文将解释只送给原来抛出未识别措辞的解析点；不改原文、不覆盖已识别规则、显式manifest字段、冲突或评分示例。每条解释必须实际解决对应失败，未使用或伪引文拒绝。非空限制只支持既有三个可执行flag，其他算法约束仍是能力边界，不能伪称被表达。

明确限制：引用存在、未覆盖已知约束和内部一致不等于语义正确性证明。LLM仍可能误读引文，必须用独立oracle验收。条件规则、矛盾声明、列顺序冲突等先进入恢复状态供LLM查证或明确未决，首版不让rules改写它们。显式manifest恢复仍只允许输出overlay和未识别原文规则规范化，不准换目标/输入列。

保存原错误/失败动作/原文和规范化来源；解释/模型缓存绑定rules、读入源码及原包。共享训练＋恢复≤3请求；HTTP失败不自动重试，已结算坏JSON可在原预算内修复。无client/local控制保留原严格行为。没有把未知规则直接忽略的后门。
