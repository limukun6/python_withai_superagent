## 哪些问题已经改变了实际结果

**读错主指标会换掉最终模型。** 对同一个匿名训练包，两次都从统一命令启动，使用相同的 460 行训练数据和相同的每路径 10 次拟合上限。旧版十次拟合，优化 accuracy 并选了 KNN；修复版九次拟合，各次试验使用 macro-F1，选了 NuSVC。随后打开的同一批 160 行合成留出中，macro-F1 由 0.7014 到 0.7628，准确率从 140/160 到 142/160。这个对照验证目标在完整流程中生效，不能外推为真实任务平均收益。[旧版](../research/lifecycle_audit_1124/goal/before/result.json) · [修复版](../research/lifecycle_audit_1124/goal/after/result.json)

**“换了划分”与“换了一批题”需要两个字段。** 原 Task2 复核的 1,314 行中有 248 行已在首轮出现，972 个标题组中重复了 190 个；原记录的独立确认标记为真。Task1 实际复核了 1,625 行，其中 377 行、368 个组重复，最终选型记录引用的依据只有首轮。两项任务每次拟合内部的训练组与当次评价组交集均为零，这些重复发生在两轮评价之间。新日志写出两层覆盖，并把独立评价标记限于最终使用的评价行和组都无交集。两个模型可以仍然使用相互重叠的训练集。[逐任务覆盖](../research/lifecycle_audit_1124/confirmation_coverage.json) · [记录实现](../superagent/ab_run.py)

**完全分开提名和批准，会出现另一种失败。** 每次只在第一半确认组提名一个方案，再让第二半决定是否采用。每折的第二半只有 309–341 行。十个决定中有三次提出改选，最后都被否决。这挡住了外层少对 22 题和 42 题的两次改选，也否掉了一次外层多对 7 题的逐题融合。最后的交付与原双模型逐题一致。两轮轮换使用同样的 6,608 道训练内题，分别解读。[初始封存](../research/lifecycle_audit_1124/selection_first_seal.json) · [决策与输出](../research/lifecycle_audit_1124/selection/)

| 同轮 6,608 题上的答对数 | 第一轮 | 调换学习与外层评价组 |
|---|---:|---:|
| 原双模型 | 4,722 | 4,754 |
| 上轮真正交付的自主选择 | 4,688 | 4,753 |

**损坏一个可选模型可以连累健康模型。** 对真实固定版本文件做四种离线资格检查。旧版在 BGE 目录存在但配置文件缺失时抛错；修复版登记缺失，只排除 BGE，其余五个仍可选。全部完好、完全缺少 BGE、缺少共同参考模型也按登记处理。最后一种情况返回通用训练入口；本次实测的是候选资格，未用缺失权重重新训练或打分。[探针方案](batches/lifecycle_asset_probe_20261124_zh.md) · [旧版](../research/lifecycle_audit_1124/assets_before.json) · [修复版](../research/lifecycle_audit_1124/assets_after.json)

## 按照什么顺序继续

1. **A 做任务契约、失败交付，B 验证可选方法在同一入口可达。** 用六份匿名开发包覆盖表格、文本、图像，兼有二类、多类、非 accuracy 和正类顺序变化。在同一份程序上改变文件名、候选顺序、可选权重可用性。要求所有有声明的指标在每一次试验和最终选择一致，有效方法仍可选，非法权重不会加载，输入表意不足时记录原因。另用预先给出的时间列和实体列检验训练到评价的时间方向和实体隔离，缺适配器时明确报告。中断注入后，有已验证模型的路径须能跨进程交付同样预测、标记部分完成，额外训练和 API 均为零。
2. **B 优先做“增加有效反馈”的实验。** 从训练特征和初步误差提名一个挑战模型，再与两个基础模型在两块互不重叠的分组验证上生成折外预测。三个模型各做两折最多六次分类器拟合，最终三个模型重训最多三次，合计最多九次，落在团队每路径十一拟合的上限内。固定同一批行、候选、确认信息和可用拟合额度，对照原双模型、原选择器和新选择器。留出外层单独计分，报告改对与改错、净增、主要任务指标、按组区间、逐折方向、重训和推理代价。开发晋级线为五折至少四折净增、累计至少五题且配对 95% 区间下限高于零，再去预先登记的新匿名任务复验。两轮历史 Task2 不能替代这一步。
3. **双方冻结并检验迁移。** 在上述开发门槛通过后，用同一次提交、入口、能力目录和每任务账本跑所有最终报告任务；在运行中保留原模型的退路，由 Agent 根据记录决定。启动前固定数据、版本、预算和评分程序。正式测试只在最终评估环节打开。时间仍紧时，优先交付能从清洁环境预测的正确模型，并把仍缺证据的改进列在研究部分。

## 如何复算

使用项目固定的 Python 3.11 环境。从课程原包只读取两份 README 与训练成员。此命令核对十个封存决定、全部逐题输出、历史分区哈希、匿名对照的拟合记录及两次预测。给出权重目录时还会真正执行四个资产检查。全部复算无需新增分类器拟合或模型 API。

```bash
python -m scripts.verify_lifecycle_audit verify /path/to/course-zips --weights /path/to/pretrained_weights
```

要重新训练匿名对照，可在空目录运行 `python -m scripts.audit_anonymous_goal prepare runs/goal-fixture`，再分别用 `python -m scripts.audit_anonymous_goal run runs/goal-fixture CHECKOUT runs/unique-output` 指向原版和修复版源码。每个版本使用独立输出目录。

匿名对照新增十九次实际分类器拟合。两轮决策回放复用基础模型和既有融合权重，只作十次提名与审核；初稿汇总程序重复传入了正确题数字段，修正后逐一比对，修正前封存的十个决定与十份预测文件哈希全部一致。发布指定验证与课程测试在本次复算的成员读取白名单之外。历史资格与分数的源码哈希核对请使用原冻结提交。[复算程序](../scripts/verify_lifecycle_audit.py) · [证据目录](../research/lifecycle_audit_1124/) · [原冻结版本](https://github.com/limukun6/python_withai_superagent/tree/bcea278942f6770bf30fdc4b52094bbc8da1a7ac)
