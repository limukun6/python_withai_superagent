## 谁决定这一步做什么

人事先实现通用工具、数据适配、候选生成、评分方法和预算约束。启动后，Agent 读取任务说明、辨认数据类型和指标，用训练数据生成可用方法，在训练内留出数据上试验。每轮它结合已有成绩、预测错误、候选之间的差异和剩余预算，决定继续探索、复核、组合，或者停止并交付模型。默认规划器在本地运行。研究人员在两次启动后均未干预，没有指定候选、试验顺序或最终赢家。

| 从空目录启动 | Agent 最终选用的方法 | 指定验证准确率 | 实际拟合（含重训） |
| --- | --- | ---: | ---: |
| Task1 优惠券 | CatBoost 加训练数据支持的字段交互 | 1533 / 2030，75.52% | 10 |
| Task2 标题偏好 | 12 层 MiniLM 加基于训练语料的熟悉度特征 | 684 / 940，72.77% | 10 |

封存两个模型和预测后才读取指定验证标签。训练时记录实际打开的包成员，工作人员在新进程从两个封存模型各重复预测，两次输出逐字节一致。把源码、两份模型、四套离线编码器、预测和日志装进工程包并解压后，两份验证输出仍一致。工程包可独立整合，课程最终 `report.pdf`、AI 使用声明和正式评测材料由团队另行汇编。历史标题分数 689/940（73.30%）保留原版本归属。

逐步还原 20 次真实决策，每次只给 Agent 当时已经观察到的反馈。反转候选显示顺序，20 次均得到同一动作。把包和目录匿名化，并给标题两列改名，两项任务的划分和 20 次完整候选排序都相同。把两个已测候选收到的反馈互换，表格任务有 42/82 次、标题任务有 51/120 次改变下一步。交换反馈是离线检验，这 93 次变化反映的是决策是否使用反馈。

## 让 Agent 改进自己判断实验价值的方法

递归自我改进（RSI）的基本想法是，让当前版本也能改进产生下一版的方法。一个后继版本若通过独立检验，便可以继续提出下一代。STOP 探索了让改进程序作用于自身；Darwin Gödel Machine 保存不同版本，并用后续实测筛选代码改动。我们借鉴版本继承和检验机制，把允许修改的范围限制在规划器如何估计探索收益。[STOP](https://arxiv.org/abs/2310.02304) · [Darwin Gödel Machine](https://arxiv.org/abs/2505.22954)

Agent 在试一个新方法前先预测成绩。拿到实际反馈后，它用两者的偏差提出一份新规则，调整“这种新方法值得优先试吗”。原规则和新规则各自预测接下来两个不同新方法的训练内成绩，预测误差平均至少降低 0.003、任一次退步不超过 0.03，Agent 才采用新规则。通过的版本可以继续提出后继版本。采纳后适当加大下次修改幅度，拒绝后缩小幅度。每次任务从原规则启动，至多提出三版。

### 四组真正从头运行的对照

四项开发任务分别留出 25% 用于最后检验。每项两组使用相同数据、训练随机种子、候选、编码器、时间和九次拟合机会。两组都用正式 `solve` 入口从空目录完成训练和交付。所有八份预测固定后，才统一读取外层标签评分。[实验约定](../research/rsi_planner_1125/protocol.json)

| 开发任务 | 各自的指标 | 原规划器 | 开启自改 | 可作出裁决的提案 / 全部提案 |
| --- | --- | ---: | ---: | ---: |
| Wisconsin 数值表格，143 行 | 平衡准确率 | 89.84% | 89.84% | 0 / 1 |
| 短信分类，250 条 | 宏平均 F1 | 0.8529 | 0.8529 | 1 / 2 |
| 手写数字，450 张 | 准确率 | 97.78% | 97.78% | 1 / 2 |
| 新生成的多类类别表格，320 行 | 宏平均 F1 | 0.7655 | 0.7655 | 1 / 2 |

7 个提案里，4 个到预算耗尽时还没有足够的新实验作判断。其余 3 个中，短信和手写数字的预测误差分别增加 0.00910 和 0.04723；类别表格减少 0.00038，未达到事先设定的 0.003。Agent 保留了原规则。四组逐行输出均完全相同。单元测试另用了可控反馈，验证好规则确实可以生效、改变选择并产生下一代。

实验有两处实际参数与起草时有出入。每组运行时限为 600 秒，原计划为 900 秒；八组均在 81 秒内完成并用完九次拟合。抽取短信子集实际使用 602911，原计划为 70931；两组使用同一子集、同一划分。短信结果只对应实际使用的样本。执行前还移除了观察器额外施加的每个子进程一次拟合限制，正式执行器继续按组件核算所有拟合。

## 把多个任务的训练经验放在一起

单个任务里可裁决的提案太少，因此补做跨任务回放。每一代只能用更早任务的训练内记录提出改法，先固定参数，再打开后续任务的训练记录。平均预测误差至少降低 0.003、任一任务退步不超过 0.02，且至少改变一个历史可行动作的首选，方可采用。这个实验只衡量对已做实验的预判，并记录新规则会怎样排列当时可用的选项。[跨任务实验约定](../research/rsi_planner_1125/archive_protocol.json)

| 提案 | 接受检验的训练记录 | 相对父版本，平均预测误差降低量 | 首选会改变的次数 | 自动裁决 |
| --- | --- | ---: | ---: | --- |
| 第 1 版，源自原规则 | 标题 | +0.00356 | 1 / 9 | 采用第 1 版 |
| 第 2 版，源自第 1 版 | 数值表格、短信 | −0.00436 | 2 / 15 | 保留第 1 版 |
| 第 3 版，源自第 1 版 | 手写数字、类别表格 | −0.00054 | 0 / 15 | 保留第 1 版 |

额外把第 1 版和最初规则直接比较。在产生和采用第 1 版时尚未使用的后四份记录中，预测误差两项降低、两项增加，等权平均增加 0.00122，30 个可选动作列表中有 3 个首选会改变。具体是两次从试新方法转向复核已有方法，一次转向立即停止。这些是回放中的顺序，无法据此推算如果重跑整条路径会多答对几题。现有结果支持继续使用已验收的默认规划器。下一项有区分力的研发问题是让 Agent 预测“哪一个动作更值得占用一次机会”，用同一训练划分中两种动作都实际做过的记录检验，并为无法比较的动作保留未知。

## 复现与费用

课程运行用统一入口 `python -m unified_agent solve TASK.zip --prediction-input FEATURES.zip --run-dir runs/new --output runs/new/predictions.csv`。在本研究分支的这条命令末尾加 `--self-review` 可开启实验。每次试验前的预测、决策依据和修改历史分别保存在运行目录的 `agent/policy_review.json`、`agent/decisions.json`。完整回归通过 749 项。

- 工程包文件名为 `SuperAgent-autonomous-d501807.zip`，SHA-256 为 `48dbfddee80f15bc056eb1daa9c3f9f306cbba19e3d2236a308ace22c260a2f5`。重建时从经核验的源版本运行[打包与验收程序](../scripts/confirm_submission_floor.py)，并使用[冻结的原始包和源码指纹](../research/rsi_planner_1125/floor_protocol.json)。
- [成对实验程序](../scripts/run_planner_self_review.py)依次运行 `prepare RUN_ROOT --sms SMS_ARCHIVE`、`run RUN_ROOT --weights WEIGHTS_DIR` 和 `score RUN_ROOT`。运行根目录内需要此前验收的 `floor/` 和对应源码 `pinned-source/`。每次独立复验用新的目录。
- 运行 `python -m scripts.replay_planner_review_archive RUN_ROOT` 生成跨任务回放，然后用 `python -m scripts.summarize_planner_self_review RUN_ROOT NEW_RESULT.json` 独立核对模型包、预算、逐行预测和采纳条件。
- 本轮两项 Released 验收用 20 次分类器拟合，四组配对另用 72 次，回放零次。模型 API 调用合计 0 次，模型 API 费用 ¥0。正式测试集和课程将发布的 Unseen 任务均保持封存。
