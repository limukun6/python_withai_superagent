# 第三步候选组合实验

2026-11-19，文本任务开发实验，两个外层划分 43111、43117。

## 实验设计

三组分别使用现有本地搜索、固定组合、基于前两步证据生成的组合。固定组合为词 TF-IDF 加线性 SVM，C=1.0。前两步相同，第四步采用基线的 word_char_stats_C0.3。候选复核和最终重训复用现有执行器。每组预算为四次搜索、前三名各追加两次复核、一次重训，共 11 次拟合。

启用现有 ErrorSlices，从内部训练数据拟合分组阈值，再对内部搜索预测分组。独立重建了前两次预测的错误分组，与日志逐项核对通过。两个有训练的分支前两步预测一致，第四步候选一致。执行器的完整运行、复核、重训、11 次拟合及零 API 调用检查全部通过。

实验只读取发布包训练数据，保留原预留分区，外层使用 shared_text 分组避免共享文本。全部候选和模型冻结后再评分外层数据。

## 结果

| 外层划分 | 外层样本数 | 基线准确率 | 固定组合准确率 | 反馈组合准确率 | 新组合进入复核 |
|---|---|---|---|---|---|
| 43111 | 1328 | 66.7169% | 66.7169% | 66.7169% | 否 |
| 43117 | 1327 | 66.1643% | 66.1643% | 66.1643% | 否 |

两次反馈组合都产生与固定组合完全相同的第三步配置。按预先记录的复用规则，反馈组复用固定组完整路径和模型，保存对应提案。三组逻辑预算各 11 次拟合，两个划分共 66 次逻辑拟合，实际新增 44 次拟合。反馈组的结果属于配置相同后的结果复用。两组开发划分也存在数据复用，不能当作独立确认样本。

运行耗时 282.63 秒，API 调用和 API 费用为零。三组最终全部选中 word_char_stats_C0.3，同一划分的外层预测逐项一致。

新组合在内部搜索上的准确率分别为 62.0884% 和 62.2766%。相对于前两步中最好的字符模型，分别改对 134、140 个样本，同时新增 151、163 个错误，净变化为 -17、-23 个。训练与搜索的准确率差分别扩大至约 38、37 个百分点。原生成器因差距大于 15 个百分点选择线性 SVM，这次改动没有实现预期改善。

## 暴露的结构问题

43111 的参照字符模型在高词语重叠组上相对整体表现最差，约低 5 个百分点。43117 的最弱组为长文本，约低 2 个百分点。现有组合器只在最弱组恰好是高未见词比例、且低于整体超过 3 个百分点时切换字符表示。其他情况落入相同的词表示分支。因此不同错误分布在本轮产生了相同提案。

动作范围还需要扩充到已观察的问题。当前组合只改变表示和分类器，无法直接表达如何修复高重叠文本里的局部编辑错误。训练与搜索差距大也不足以单独支持换成线性 SVM。应同时检查表示、正则化和对应错误组的预测变化。

本轮结果支持“当前这条组合动作在两个开发划分上未改善最终选择”。由于反馈和固定组合配置相同，尚无法估计证据选动作的独立收益。其他组合、完整组合搜索、LLM 决策器及其他任务的效果仍待验证。本轮采用第三步受控干预，以测量一个动作的贡献。

## 后续研发安排

1. 先补证据与动作的对应。针对高重叠样本检查已有 edit_pair 候选能表达的局部对齐编辑特征，针对训练与验证差距检查正则化动作。每个动作保存参照试验、目标分组、预期变化和失败条件。
2. 在内层数据上做提案回放，比较完整证据、移除错误分组、交换分组描述后的动作。事实字段与描述分开核验。应先观察到可解释的动作变化，再投入训练预算。
3. 采用同样的第三步干预比较目标动作、固定目标动作及现有策略。主要观察目标组净改正数、整体内部准确率、入围与最终模型变化。外层数据仅在模型冻结后评分。
4. 开发阶段出现有解释价值的改善后冻结规则，在新划分复验。开发结果用于调整规则，复验结果单独记录。表格任务另行选取可执行的诊断与动作。

按本机本轮耗时估算，两个划分、三个不同动作分支约需 7–10 分钟。若拟合更重的编辑或混合表示，先测一次，再更新预测。上述时间只覆盖运行，代码与诊断开发另需工时。

## 复现与文件

在仓库根目录执行以下命令，输出目录须使用新名称。

```powershell
.\.venv\Scripts\python.exe scripts/run_composition_study.py --output runs/composition_study_v2
```

本轮目录为 `runs/composition_study_v1`。`protocol.json` 记录数据与源码哈希、预算和规则。每个划分保存提案、内部错误分组、候选轨迹、复核与模型。`results.json` 保存评分和配对差异，`completion.json` 保存完成状态、实际拟合数和耗时。

实验脚本通过现有 DecisionPolicy 接口控制第三个动作，固定组只在实验进程中替换候选注册器。部署搜索策略的实现仍为本轮基线版本。
