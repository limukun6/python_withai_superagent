## 2. 一次输出差异不等于反馈效果 → 同提示核对与新划分审计 → 输出波动必须报告

每任务四个Flash组的首次请求，去checks/memory后公共字段逐项相同，历史仅同一个完成anchor。raw两次完整messages相同，checked两次完整messages也相同；模型/端点/温度等公共设置相同。A30只取这些预登记位置，不挑成功/错误状态。

首次选择：Coupon四臂均catboost_depth6_reg3.0；偏好对R0/E0/R1均word_C0.1，E1为word_char_C0.05。即偏好对**同一checked完整提示的两次调用，返回不同候选**。这是观察到的输出波动，不假定具体服务器原因；不能把所有组间差异解释成反馈或调度的纯因果收益。

A30把这8个提案冻结，在两个从未放进提示的新训练内划分17171/17181测动作。相同动作去重，只有3个不同配置×2划分=6实际fit，16逻辑评价复用其中10项，0新增API、34.140秒，未使用外层val。

## 3. 当前结论与下一个结构修复

已支持：正式六组可执行、按真实训练记账与预算停止、强方法实际可达、模型可重载；原始反馈已经能让模型读懂失败并换方法（另见A28）。额外核对不会自动让选型更好，模型还会在合法候选内陷入局部调参，同提示选择也可能变化。

下一批A31/A32将单独测一个通用动作门槛：前几次探索优先覆盖不同已注册路线，覆盖足够后再放开同路线调参。按能力元数据工作，不按任务名指定赢家，不增方法/fit/API额度，不改B的复核/停止规则。先做0API原轨迹审查和接口验证，再以同版本开/关、相同固定调度比较；不能直接拿A29旧源码当新版唯一控制。
