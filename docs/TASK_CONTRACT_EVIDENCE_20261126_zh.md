# 从题面建立可执行的任务契约

正式入口仍是 `python -m unified_agent solve`。它从任务说明、训练文件结构和实际标签建立契约，再让调度器选择实验。题面中的列名用于解释字段，任务身份不参与模型选择。

| 队友提出的问题 | 复核和修复 |
|---|---|
| 数组没有表头，题面明明写了列名 | 修复前，原始 Task1 的契约确实是空表。现在按题面顺序核对训练数组的宽度、列名唯一性和目标列隔离，再保存 21 个列名。原文第 14 列为 `CarryAway`。重新加载模型时也会检查预测数组的宽度。 |
| 理解类别与指定正类混在一起 | Task1 分别记录 `1 = accept`、`0 = decline` 和主指标 accuracy。Task2 从已验证的成对方向记录 1 对应左侧胜出、0 对应右侧胜出。训练反馈可以按类别含义报告召回率。二分类题若明确要求某类的召回率，程序会把该名称对应到训练标签后按它评分，正类可以是 0。 |
| `report macro F1` 会变成 accuracy | 11 月 25 日的版本已经修复这条路径。本次回归再次检查 README、manifest 的常见拼写、冲突和未声明情况。没有主指标时可见默认来源，已宣布但无法解释的主指标进入未解决记录。 |
| 任务禁止某种方法，候选仍会出现 | 统一入口识别禁用预训练资产、禁用外部数据、只准线性模型。共同目录、生成的候选、可选的大模型提案和训练执行器都受此约束。只准线性时同时排除非线性核和双模型软投票。识别为强制条件但缺少执行规则时，在拟合前报告原因。 |
| 不常见的文件名容易混淆训练与评估 | 文件角色可以来自 manifest、说明或明确的分区文件名。读取课程包时，Task1 每个划分登记两个数据文件，Task2 每个划分登记一个。压缩包中的 macOS 辅助条目会被排除。只检查评估成员的名称，正式训练读取训练数据。中性文件名与单表分区有专门回归。 |

## 大模型能补什么

提供结构化任务时，可在 manifest 加上 `restrictions`。它接受 `no_pretrained_assets`、`no_external_data`、`linear_only` 三个布尔字段。当前对禁用外部数据采用保守解释，外部训练的现成权重也不参与。标签字典写在 `label_meanings`，只有明确指定的评分正类才写入 `positive_label`。

默认入口在本地核对题面。需要启用校园模型时，可按团队用量账本配置 `--task-analysis flash`。[开题模型配置](TASK_OPENING_V1_1126_zh.md)

确定性解析能读懂的声明直接按原文处理。对无表头数组，遇到有字面字段名单、列数也吻合，但排列含义不够直接的说明，可以通过已配置的课程模型请求一次引文选择。只发经过筛选的短引文和训练列数，答复只能选一个引文编号或给出空值。Python 再核对原文里的次序、完整字段数和唯一性。采纳的描述标为 `proposed`。主指标、文件访问权限、方法禁令和最终模型均有独立的执行规则。

缓存保存在本地。键包含原说明的 SHA-256、训练列数、目标、标签域、引文、模型和抽取规则版本。不同结构的任务可以复用同一份说明而得到各自的检查结果。原文有冲突、答复越出字段范围或模型选择弃答时，系统保留未知状态。小型抽取与开题读题共享当次已配置的阅读机会，单个抽取的最大输出是 128 token。

两份独立人工说明分别做了一次真实校园 DeepSeek-V4.1-Flash 核验。第一份把名单和说明句分开展示，模型弃答。第二份发送带实际名单的完整原句，模型引用了对应引文，四个字段进入 `proposed`。断开模型重新运行，第二份契约逐项相同，缓存命中，新增调用为零。两次用量分别为 136／116 和 132／91 个输入／输出 token。按课程更新后的空闲价，合计 **¥0.001096**，两笔已核对 B 侧账本。这两个例子验证了接入行为。陌生说明上的抽取覆盖率还需要更多独立样本。[单次接入核验](../scripts/verify_contract_reader_once.py)

## 在一次运行中检查什么

在 `run/agent/task_contract.json` 中查看字段的值、来源、状态和文件角色。在 `history.json` 里可以对照实际拟合配置、主指标和按已声明标签含义计算的召回率，`decisions.json` 给出每一步真正可选的动作。未知方法限制的记录在 `run_outcome.json` 中以 `method_restriction_unresolved` 标识。[覆盖案例及正式入口测试](../tests/test_task_declarations.py)

## 课程题与交付包复验

两份原始发布包分别从空目录运行默认 `solve`，选择方法时只使用训练划分。先封存两个预测文件，随后一次性对照课程指定验证标签。Task1 答对 **1,533/2,030（75.52%）**，选中 `supported_field_interactions`。Task2 答对 **684/940（72.77%）**，选中 `minilm_l12_with_corpus_familiarity`。每题各拟合 10 次，均含最终重训，两题模型 API 调用合计为 0。两题的逐行预测均与上一个自主交接版一致。个人交付包通过独立 Python 进程重新加载两个模型，2,970 行预测逐字节相同。正式测试保留。

在本机装有四套文本编码器时，无限制的匿名文本任务有 63 个可选方法，其中 8 个使用预训练资产。禁止预训练后仍有 55 个方法可选，预训练候选为零。另一道匿名题要求只用线性分类器，并按标签 0 的召回率选模。统一入口按该指标完成训练并独立重载预测。此次源码完整测试通过 801 项。[逐题验收与用量](../research/task_contract_1126/results.json)
