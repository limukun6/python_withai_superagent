# 指标把类别 0 列为正类时，Agent 也能复核第三个模型

同一个二分类任务可以把概率列排成 `[0,1]` 或 `[1,0]`。原入口在第二种排列下会跳过相似案例投票的复核。现在提名、计数和最终预测统一使用任务契约给出的类别顺序。

用之前自主取得 710/940 的模型保存的三份训练内反馈回放，两种类别顺序下的提名、各权重答对数和确认计数全部相同。回放没有新增拟合。[逐折计数](../research/paired_encoder_search_1127/adviser_order_training_replay.json)

另外，从头跑同一个电影台词任务，仅在说明中指定类别 0 为正类。Agent 在首份内部检查提出给案例投票 25% 权重，另两份反馈分别与原模型打平和少答对 4 条，于是保留单独的 GTE-small，最终案例权重为 0%。共 15 次实际拟合、模型 API 0 次，另起进程复现全部 450 条预测。与先前运行有 44 条输出变化。最早的分歧发生在第 2 次试验，同一个可选模型本次训练超时。此次未重开电影留出答案，不能用这 44 条判断涨跌，也不能把路径变化归因于类别顺序。[实际复核反馈](../research/paired_encoder_search_1127/adviser_order_review.json) · [两份最终模型和最早分歧](../research/paired_encoder_search_1127/adviser_order_route_evidence.json)

早期封存回执中名为 `actual_share` 的字段记录了提名权重。实际使用的权重由最终模型确定，已补上区分两者的回执，新的封存也会分别记录它们。
