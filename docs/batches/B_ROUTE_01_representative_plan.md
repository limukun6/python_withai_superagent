# 第一次试某类方法时，应该先试哪个参数值

同一方法有多档参数时，原本地调度器常常按共同目录顺序取第一档。检验一条与任务名称无关的决策规则。保留全局第一个基准方法、方法类别的原优先次序、全部候选和确认规则。在首次探索另一个方法类别时，如果可信目录给出至少三个只在一个正数参数上变化的配置，选择最接近全目录对数中位数的可行配置。相同距离沿用原顺序。已有尝试、参数不满足条件、缺可信目录或只有一个合法选项时沿用原选择。固定对照和交给语言模型的候选及次序保持原样。这里仅检验如何提出第一个参数，后面的晋级仍由实测决定。

零拟合回放预先指定九条真实轨迹：优惠券一条、标题两条、MRPC 两条、短信一条、服装一条、Dry Bean 和 Car 的原目录对照各一条。先逐动作复现原决策和实际采纳记录，再逐条找新策略的首次分歧。首个分歧之后的原历史只能作单步策略检查，无法推断新策略完整成绩。回放不加载外层留出标签，不生成新预测，不调用模型 API。记录入口、原执行代码、候选、优化输入和内部划分身份。

真实小试在回放之后进行，下一批单独登记。两个 Released 的初筛都必须披露，不按某个分数选任务。若任一任务的两种策略存在首次分歧，优先使用相同的预登记全菜单、两份内部划分和训练次数做实配；没有动作分歧的路径沿用真实既有结果。继续封存课程正式验证、测试及 H。
